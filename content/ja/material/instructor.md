# 講師ガイド：App シナリオを一本の流れで実施する

## 使用する教材

参加者には [App の目次](../app/README.md) を配布します。CLI 独立コースと Mona Mayhem は補講用の参考資料で、本編の途中では移動しません。演習対象は各自の Tailspin Toys コピーです。教材リポジトリ内でサンプルアプリの演習を実行しないでください。

参照元：`github/dev-days` の開催・運営資料、`github-samples/copilot-workshops` の App シナリオ。参照コミットとファイルは `content/ja/sources.json` に記録しています。参照元への変更送信は行いません。

## 180分枠の運営案

この教材セット独自の配分案です。実測の所要時間ではありません。演習0・1の導入は事前に済ませます。元シナリオの60〜90分に、CLI への切り替え支援とレビュー時間を追加します。

| 内容 | 分 |
| --- | ---: |
| 導入セッション（Dev Days の App スライドを使用可） | 30 |
| 環境・対象リポジトリ確認（演習0・1） | 15 |
| 星評価・PR・マージ（演習2） | 20 |
| 指示更新・PR・マージ（演習3） | 15 |
| 休憩 | 10 |
| フィルター計画・実装・quality-checks（演習4） | 30 |
| MCP 検証（演習5） | 20 |
| レビュー・マージ／Agent Merge デモ（演習6） | 15 |
| Canvas デモ・優先順位整理（演習7） | 10 |
| 振り返り・手動 Automation デモ（演習8） | 10 |
| 質疑・切り替え予備 | 5 |

CI 待ちや環境構築が長引く場合は、後半をデモにして未実施の項目を記録します。「全演習完了」とは案内しません。Canvas・Automation を全員で実施する場合は、追加枠を確保します。

## 開催前のリハーサル

- 自分の非公開コピーで App 演習0〜8を順に試し、App/CLI・Node.js のバージョン、テンプレート SHA、OS を記録する。
- 演習2・3のマージが演習4に引き継がれることを確認する。CLI コースで先に作る publisher helper の存在を仮定しない。
- 各章で App を停止して同じ worktree から CLI に切り替え、App に戻って差分が同じことを確認する。
- App 用と CLI 用の利用ポリシー、残り利用枠、ネット接続、必要な GitHub 権限を確認する。UI 変更と認証・利用枠の問題を切り分ける。
- 星評価の null ケース、フィルターの複合条件・解除・該当なしを確認する。seed にない条件はテスト用データで検証し、実 UI 操作と区別する。
- MCP 用 Chrome と E2E 用 Chromium を区別する。接続失敗はプロセス・CLI 設定と再起動を確認し、手動検証へ切り替えた場合は MCP 未実施とする。
- PR Readiness の YAML エラーなど既知の問題は [CLI の参考資料](../cli/6-custom-agents.md) を参照する。確認済みの修正を演習開始前に適用する。
- 終了時に開発サーバー・演習用 Codespace・不要な定期実行を停止する。PR や未保存の変更を消さない。

## 当日の切り替え判断

ボタンが見つからない場合は章・目的・画面を確認し、約5分で解決しなければ [共通手順](continuation.md) とその章の CLI 手順へ案内します。ネットワーク・権限・利用枠の問題は CLI でも解決しないことがあるため、ペア作業か講師デモに切り替えます。

演習6の通常マージ、演習7の Markdown での整理、演習8の単発要約は到達目標の一部を満たしますが、App 固有機能の体験には代わりません。
