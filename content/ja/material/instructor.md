# 講師ガイド：App シナリオを一本の流れで実施する

## 使用する教材

参加者には [App の目次](../app/README.md) を配布します。CLI 独立コースと Mona Mayhem は補講用の参考資料で、本編の途中では移動しません。演習対象は[修正済みの非公開テンプレート](https://github.com/iwizsophy/dev-days-tailspin-template)から作る各自の Tailspin Toys コピーです。参加者には事前に閲覧権限を付与し、取得先を上流に戻さないでください。教材リポジトリ内でサンプルアプリの演習を実行しないでください。

参照元：`github/dev-days` の開催・運営資料、`github-samples/copilot-workshops` の App シナリオ。参照コミットとファイルは `content/ja/sources.json` に記録しています。参照元への変更送信は行いません。

## 180分枠の運営案

この教材セット独自の配分案です。実測の所要時間ではありません。演習0・1の導入は事前に済ませます。元シナリオの60〜90分に、App の操作支援とレビュー時間を追加します。

| 内容 | 分 |
| --- | ---: |
| 導入セッション（Dev Days の App スライドを使用可） | 30 |
| 環境・対象リポジトリ確認（演習0・1） | 15 |
| 星評価・PR・マージ（演習2） | 20 |
| 指示更新・PR・マージ（演習3） | 15 |
| 休憩 | 10 |
| フィルター計画・実装・quality-checks（演習4） | 30 |
| MCP 検証（演習5） | 20 |
| レビュー・マージ／Agent Merge デモ（演習6） | 15 |
| Canvas デモ・優先順位整理（演習7） | 10 |
| 振り返り・手動 Automation デモ（演習8） | 10 |
| 質疑・切り替え予備 | 5 |

CI 待ちや環境構築が長引く場合は、後半をデモにして未実施の項目を記録します。「全演習完了」とは案内しません。Canvas・Automation を全員で実施する場合は、追加枠を確保します。

## 開催前のリハーサル

- 自分の非公開コピーで App 演習0〜8を順に試し、App/CLI・Node.js のバージョン、テンプレート SHA、OS を記録する。
- 演習2・3のマージが演習4に引き継がれることを確認する。CLI コースで先に作る publisher helper の存在を仮定しない。
- [UI 確認表](ui-check.md)に沿って現行 App の操作経路と画像を検証する。CLI の緊急対応は、本編と別の作業保全リハーサルとして確認する。
- App 用と CLI 用の利用ポリシー、残り利用枠、ネット接続、必要な GitHub 権限を確認する。UI 変更と認証・利用枠の問題を切り分ける。
- 星評価の null ケース、フィルターの複合条件・解除・該当なしを確認する。seed にない条件はテスト用データで検証し、実 UI 操作と区別する。
- MCP 用 Chrome と E2E 用 Chromium を区別する。接続失敗はプロセス・App の MCP 設定と再起動を確認し、手動検証へ切り替えた場合は MCP 未実施とする。
- 教材用テンプレートの YAML・MCP 修正は適用済み。配布版 v2026.09.13 と開始コミットを確認する。演習済みの検証リポジトリを開始用として配布しない。
- 配布元 WORKSHOP.md の依存監査の未解決事項（Critical を含む）を確認し、依存更新と再検証を本番配布前に完了する。機能テスト成功だけで配布可とは判定しない。
- 終了時に開発サーバー・演習用 Codespace・不要な定期実行を停止する。PR や未保存の変更を消さない。

## 当日の操作支援と緊急対応

1. 章・操作目的・現在の画面を確認し、[UI 確認表](ui-check.md)に差分を記録します。画面上の位置だけで判断せず、機能名・対象リポジトリ・セッションの状態を照合します。
2. 講師が検証した現行 App の操作経路を案内します。見つからない機能に対して推測の操作を案内しません。
3. 参加者環境で使えなければ、同じ App 操作を講師デモまたはペア操作で示します。見ただけの場合は「デモ確認」とし、自分での実施と区別します。
4. 作業を保全して実装を続ける必要がある場合だけ、[講師専用 CLI 手順](emergency-cli.md)を使います。時間が経っただけで CLI へ自動的に切り替えません。App 操作は未完了と記録します。

環境・権限・利用枠の問題は UI の変更と分けて記録します。講師環境でも機能を確認できない章は延期し、実施できると案内しません。通常 PR、Markdown、単発要約を Agent Merge・Canvas・Automation の実施に数えないでください。

## 検証の記録
