# 第3章：エージェントでゲームを実装する

この章では、Copilot に設計の計画立案だけでなく、実際のコード実装までを自律的に担当してもらいます。人間が 1 行ずつコードを手書きする代わりに、「何を実現したいのか」という目的と要件を Copilot に伝え、関連する複数ファイルを横断して変更してもらいます。

## タスク1：対戦処理をつなぐ

1. エージェントによる実装環境を準備します。
   - **VS Code：** Copilot Chat パネルのモード選択で **Agent** を指定します。
   - **CLI：** 通常のインタラクティブなコーディングセッションへ戻ります。なお、一連のタスクを自律的に継続実行させたい場合は、Autopilot を利用する選択肢もあります。
2. CLI を使用している場合は、必要に応じて `@src/pages/index.astro` をプロンプト内で明示的に指定し、対象ページをコンテキストへ追加します。
3. 次のプロンプトを入力して送信します。

    ```text
    対戦ページに、次を行うクライアント側 JavaScript を追加してください。
    1. Battle ボタンが押されたら、両方の入力欄からユーザー名を取得する。
    2. 両方が入力されているか確認し、空ならエラーを表示する。
    3. 自分たちの API から、2人のコントリビューションデータを並列で取得する。
    4. GitHub の配色を使い、1日を1つの色付き四角形としたグリッドでグラフを描画する。
    5. 2人の間に VS バッジを表示する。
    6. それぞれのユーザー名、コントリビューション合計、対象期間を表示する。
    7. 読み込み中とエラーの状態に対応する。
    8. 入力欄で Enter キーを押したときにも対戦を開始する。
    9. 今は作成済みのシンプルな UI を使う。
    コントリビューションデータの構造には TypeScript の interface を使ってください。
    ```

4. `src/pages/index.astro` などを対象として、コードの生成と修正が進行するのを見届けます。
5. 変更内容を確認し、問題がなければ採用します。
   - **VS Code：** エディター上の差分表示（インライン差分）で変更箇所を確認し、承認・適用します。
   - **CLI：** `/diff` コマンドを実行して変更内容を確認し、適用を確定します。

## タスク2：対戦をテストする

> [!TIP]
> **変更が画面に反映されない場合：** 開発サーバーを実行しているターミナルで `Ctrl+C` を押して停止し、再度 `npm run dev` で起動したうえでブラウザーをリロードしてください。

1. ユーザー名入力欄にそれぞれ `octocat` と `torvalds` を入力し、**Battle** ボタンをクリックします。
2. 色付きの正方形グリッドによって、2 人分のコントリビューショングラフが左右に並んで描画されることを確認します。
3. 片方または両方の入力欄を空にした状態で対戦を実行し、適切な入力エラーメッセージが表示されることを確認します。
4. 存在しない無効なユーザー名を入力し、API からのエラーが画面上に適切に表示されることを確認します。
5. いずれの入力欄でも、テキストを入力したあとに **Enter** キーを押すだけで対戦が開始できることを確認します。

## タスク3：フィードバックで改善する

生成された結果が期待した見た目や動作と異なる場合は、遠慮なく具体的な追加指示を出して反復的に改善します。

- 「グラフの四角形が大きすぎるので、12×12px に調整してください」
- 「各四角形にマウスホバーした際、日付とコントリビューション数を表示するツールチップを追加してください」
- 「データ読み込み中のプレースホルダー表示に、パルスアニメーションを追加してください」

VS Code の Agent モードでは、同一の会話セッション内で複数ファイルの修正や反復的なフィードバックをシームレスに続けられます。同様に CLI でも、セッション履歴を踏まえた追加指示が可能です。エージェントが保持しているコンテキスト情報は `/session` や `/context` コマンドで確認でき、大規模なコード変更を加えたあとは `/review` コマンドで品質の追加レビューを依頼できます。

## 💡 この章のヒント

- **求める動作を具体的に伝える：** 抽象的な要望ではなく、サイズ、色、挙動、エラー処理などを具体的に記述します。
- **意図から外れたら分割する：** Copilot が一度に意図を汲み取れなかった場合は、大きな課題を複数の小さなプロンプトに分解して順番に指示します。
- **採用前に必ず差分をレビューする：** 生成されたコードは盲目的に受け入れず、差分表示で確認してから適用します。
- **実装ごとに都度テストする：** 1 つの変更を加えるたびに動作を確認することで、問題が発生した際に原因箇所を迅速に特定できます。
