# 第2章：計画とひな形作成

コードを実際に書き始める前に、Copilot の計画機能（Plan モード）を活用してアーキテクチャを検討します。あらかじめ計画を立てておくことで、システム全体の構造を十分に吟味できるだけでなく、続くコード生成プロセスに対しても精度の高い前提情報を渡せます。

## タスク1：API の構造を計画する

1. 計画モードへ切り替えます。
   - **VS Code：** Chat パネル下部にあるモード選択ドロップダウンから **Plan** を選択します。
   - **CLI：** **Shift+Tab** を押して計画モードへ切り替えるか、コマンド `/plan` を実行します。
2. 次のプロンプトを入力して送信します。

    ```text
    任意のユーザー名について GitHub のコントリビューションデータを取得する、サーバー側の API プロキシを作りたいです。
    エンドポイントは https://github.com/{username}.contribs で、JSON を返します。
    ブラウザーから直接取得した際の CORS 制約を避けるため、サーバー側で取得します。
    ルートの構造、エラー処理、キャッシュ戦略を含めて実装を計画してください。
    ```

3. **提示された計画をレビューします。** 不明な点があれば Copilot へ質問し、設計に違和感がある場合は変更を提案して、納得がいくまで計画を調整してください。
4. 計画が確定したら、実装へ進みます。
   - **VS Code：** モードを **Agent** に切り替え、計画に基づく実装を依頼します。
   - **CLI：** 確認済みの計画を実装するよう依頼し、完了後に `/diff` を実行して編集内容を確認します。
5. 次の API ルートファイルが作成されていることを確認します。

    ```text
    src/pages/api/contributions/[username].ts
    ```

> [!NOTE]
> **日本語版の補足：** `.contribs` というエンドポイントの応答形式は、原文教材が前提としている仕様です。実際の HTTP ステータスコード、Content-Type、およびレスポンス本文を確認してください。もし想定どおりのデータが得られない場合は、勝手に認証情報をクライアント側コードへ埋め込んで解決しようとせず、講師とともに適切な取得方法を確認してください。

## タスク2：API をテストする

> [!TIP]
> **変更が反映されない場合：** 開発サーバーを実行しているターミナルで `Ctrl+C` を押して停止し、再度 `npm run dev` を実行して再起動してください。

1. 開発サーバーが稼働していることを確認し、別のターミナルウィンドウから次の curl コマンドを実行します。

    ```bash
    curl http://localhost:4321/api/contributions/octocat
    ```

2. コントリビューションデータを含む JSON レスポンスが正常に返ってくることを確認します。
3. 存在しない無効なユーザー名でもリクエストを試し、適切なエラーレスポンスが返されることを確認します。

## タスク3：対戦ページを計画する

1. 再び Plan モードへ戻ります（CLI では `/plan` も利用可能です）。
2. 次のプロンプトを入力して送信します。

    ```text
    次にメインページが必要です。「Mona Mayhem - GitHub Contribution Battle Arena」の対戦ページを計画してください。
    Player 1 と Player 2 のユーザー名入力欄、対戦ボタン、結果表示領域を用意します。
    この段階ではレイアウトや装飾を作り込みすぎず、シンプルな UI にしてください。
    HTML の構造、基本的なスタイル、対戦操作の流れを計画してください。
    ```

3. 提示された計画を精読し、質問や修正提案を重ねて内容をブラッシュアップします。
4. 実装を依頼します。
   - **VS Code：** Agent モードに切り替えて実装を依頼します。
   - **CLI：** 計画の実装を依頼し、`/diff` で生成された HTML と CSS のひな形を確認します。

## タスク4：ひな形を確認する

1. ブラウザーで [http://localhost:4321](http://localhost:4321) を開きます。
2. 画面上にゲームのタイトル、2 人分のユーザー名入力欄、そして対戦ボタンが配置されていることを確認します。
3. **この段階では、ボタンをクリックしてもまだ動作しませんが正常です。** ユーザー操作とデータを連携させるロジックは、次章で実装します。

画面の表示が更新されない場合は、開発サーバーを再起動したうえでブラウザーをリロードしてください。
