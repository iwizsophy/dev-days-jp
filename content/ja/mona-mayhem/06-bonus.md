# 🎉 発展課題

GitHub コントリビューション対戦アプリ「Mona Mayhem」の基本機能が完成しました。ここからは、さらなる機能追加やユーザー体験の向上を目指す自由課題（ボーナスタスク）に挑戦します。VS Code では **Agent モード**、CLI では `@file`、`/plan`、通常対話モード、および `/review` を組み合わせて自律的に実装を進めてみましょう。

## 🏆 課題1：勝者バナーの表示

2 人分のコントリビューショングラフを読み込んだあと、年間合計数を比較して勝敗バナーを表示します。

- **実装する要件：**
  - 2 人のコントリビューション合計数を比較する。
  - 数値に差がある場合は、**「🏆 {username} WINS! 🏆」** を華やかに画面表示する。
  - 同点の場合は、**「🤝 IT'S A TIE! 🤝」** を表示する。
  - CSS アニメーションや紙吹雪エフェクトを組み合わせて勝者を演出する。

- **プロンプト例：**

    ```text
    両方のコントリビューションデータを読み込んだら、合計を比較して勝者バナーを表示してください。
    多いユーザーには「🏆 {username} WINS! 🏆」、同点なら「🤝 IT'S A TIE! 🤝」を表示し、CSS アニメーションで華やかにしてください。
    ```

## 🏆 課題2：連続コントリビューション日数（Streak）カウンター

各ユーザーがコントリビューションを途切れさせずに継続した最長連続日数を算出します。

- **実装する要件：**
  - コントリビューションデータを日ごとに走査する。
  - 1 日あたり 1 件以上のコントリビューションが存在する連続日数を計算し、その最長記録を割り出す。
  - 各ユーザーのグラフ近傍に最長連続日数を分かりやすく表示する。
  - 連続日数の長いユーザー側を目立つように強調表示する。

- **プロンプト例：**

    ```text
    各ユーザーのデータを分析して、コントリビューションが途切れず続いた最長日数を求める機能を追加してください。
    各グラフの下に「🔥 Longest Streak: X days」と表示してください。
    ```

## 🏆 課題3：過去の対戦履歴の保存と一覧表示

対戦結果をローカルストレージへ永続化し、過去の対戦カードをいつでも振り返られるようにします。

- **実装する要件：**
  - 対戦した 2 人のユーザー名、コントリビューション合計数、勝敗結果、および対戦日時を `localStorage` に保存する。
  - 対戦エリアの下部に **Recent Battles** セクションを新設する。
  - 直近 5〜10 件の対戦履歴を一覧表示する。
  - 履歴データを一括消去する **Clear History** ボタンを設置する。

- **プロンプト例：**

    ```text
    比較が終わるたびに対戦結果を localStorage に保存してください。
    「Recent Battles」に直近10件のユーザー名、コントリビューション合計、勝者、対戦日時を表示し、「Clear History」ボタンを付けてください。
    ```

## 🏆 課題4：Web Audio API によるレトロアーケード効果音

外部の音声ファイル（MP3 等）を一切読み込まず、ブラウザー標準の Web Audio API のみを用いてレトロな効果音を動的生成します。

- **実装する要件：**
  - **Battle!** ボタンをクリックした際の **コイン投入音**
  - 対戦データが正常に取得できた際の **パワーアップ音**
  - ユーザーが存在しない場合や API 通信失敗時の **爆発音**
  - 音声の ON/OFF を切り替えるミュートトグルボタン

- **プロンプト例：**

    ```text
    音声ファイルを使わず、Web Audio API でレトロアーケード風の効果音を追加してください。
    対戦開始にコイン投入音、結果取得にパワーアップ音、エラー時に爆発音を鳴らしてください。
    oscillator と gain node で生成し、ミュート切り替えを付けてください。
    ```

## 🏆 課題5：対戦開始カウントダウン演出

結果画面を即座に表示するのではなく、緊迫感のあるカウントダウン演出を挟んでゲーム性を高めます。

- **実装する要件：**
  - **Battle!** ボタンが押された直後に、画面全体を覆うオーバーレイを表示する。
  - **3… → 2… → 1… → ⚡ FIGHT! ⚡** というカウントダウンテキストをテンポよくアニメーション表示する。
  - カウントダウン完了と同時に、両者のグラフがドラマチックにスライドインする演出を行う。
  - CSS アニメーションまたは JavaScript タイマーによって各段階のタイミングを緻密に制御する。

- **プロンプト例：**

    ```text
    Battle! を押したときに対戦開始アニメーションを追加してください。
    オーバーレイに「3...」「2...」「1...」「⚡ FIGHT! ⚡」を約1秒ずつ表示し、その後に結果をスライドインさせてください。
    ```

## 🏆 課題6：コントリビューショングラフの凡例表示

本家 GitHub のコントリビューショングラフと同様に、活動強度の段階を示すカラー凡例を配置します。

- **実装する要件：**
  - 活動強度のレベル（コントリビューション数）に応じた四角形を横並びで配置する。
  - 凡例の両端に **Less**（少）から **More**（多）のラベルを添える。
  - GitHub コントリビューション API のレスポンスに含まれる実際のカラーパレットを忠実に反映する。
  - ユーザーが迷わないよう、各グラフのすぐ下に自然にレイアウトする。

- **プロンプト例：**

    ```text
    グラフの下に、API の配色を使った凡例を追加してください。
    「Less」の最も薄い色から「More」の最も濃い色まで、色付きの四角形を横に並べ、レスポンスの実際の活動量の色に合わせてください。
    ```

## 🏆 課題7：対戦結果のクリップボード共有

ワンクリックで対戦結果の要約テキストをコピーし、SNS やチャットツールへ簡単に投稿できるようにします。

- **実装する要件：**
  - 対戦結果の確定後に表示される **📋 Share Results** ボタンを設置する。
  - 2 人のユーザー名、コントリビューション合計数、および勝者を含む整形テキストをクリップボードへ書き込む。
  - コピー成功時、画面上に短時間だけ **Copied!**（または **Copied to clipboard!**）というフィードバックを表示する。

- **プロンプト例：**

    ```text
    整形した対戦の要約をクリップボードにコピーする「📋 Share Results」ボタンを追加してください。
    両方のユーザー名、コントリビューション合計、勝者を含めてください。
    Clipboard API を使い、「Copied to clipboard!」という確認を短時間表示してください。
    ```

## 💻 CLI の発展的な追加練習

CLI の運用スキルをさらに高めたい場合は、以下の高度なコマンドや実践的なテクニックを試してみてください。

- **コミットメッセージの自動立案：**  
  `copilot -p "現在の git diff に対する Conventional Commits 形式のメッセージを提案してください。ファイルの変更や commit はしないでください"` を実行し、Git コミットにそのまま貼り付けられる高品質なメッセージのみを生成させます。
- **セッション記録のエクスポート：**  
  `/share file` コマンドを実行し、CLI との対話ログ全体を Markdown ファイルとして保存・共有します。
- **コンテキストと計画の可視化：**  
  `/session` および `/session plan` コマンドを実行し、CLI が作業の進捗や設計プランを内部でどのように構造化して保持しているかを確認します。

## 🎊 ワークショップの完了

お疲れさまでした！これで **Mona Mayhem: GitHub Battle** の主要な演習プログラムはすべて完了しました。

### 本ワークショップで作成したもの

- 計画立案（Plan）から実装（Agent）へと段階的に組み立てた Web アプリケーション
- レトロアーケード筐体の世界観を表現した、レスポンシブなランディングページ
- GitHub API から実際の活動データを取得し、2 人のユーザーを比較する対戦画面
- コントリビューション強度を色で塗り分けた対話型のグリッドグラフ
- エラーハンドリング、ローディング表示、キーボード操作性などのアクセシビリティ改善
- スマートフォンからデスクトップまで柔軟に適応するマルチデバイスレイアウト

> [!NOTE]
> **日本語版の補足：** 原文の振り返りには「複数ページのアプリ（multi-page app）」との記述が見られますが、本ワークショップの必須課題はメインページと API ルートの実装が中心です。ご自身が実際に実装・検証した範囲を完了成果として記録してください。

### 実践を通じて習得したスキル

| 習得スキル | 実践内容と学び |
| --- | --- |
| **コンテキストの設計** | 適切なファイルパス（`@file`）、明確な指示、および制約条件を Copilot へ的確に渡すスキル |
| **計画立案（Plan）** | コード生成を焦らず、事前にアーキテクチャや画面遷移を Copilot と検討・調整するスキル |
| **自律エージェントによる開発** | 複数ファイルにまたがる複雑な実装タスクを、エージェントへ自律的に実行させるスキル |
| **デザインの反復改善** | 大まかなビジュアル方針からスタートし、ブラウザー描画を見ながら細部をプロンプトで追い込むスキル |
| **レビューの習慣化** | 生成されたコードを盲目的に受け入れず、commit 前に必ず差分（`/diff`）を精査する習慣 |
