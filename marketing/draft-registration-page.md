# 📝 Registration Page – Dev Days

This document provides a ready-to-use template for creating your **Dev Days** event registration page.
Customize it with your local event details, such as date, time, location, and agenda.

---

## Before you start

* 1️⃣ Use the following event name format:
  `Dev Days [City Name]`
  Example: `Dev Days São Paulo`
* 2️⃣ Generate necessary event page and promotional assets using the [asset generator tool](https://gh.io/dev-day/assets)
* 3️⃣ Dev Days are open to all developers. But if you plan to cover a topic that has additional prerequisites or experience suggestions, please state this in your registration page.
* 4️⃣ Clearly state whether participants need to **bring their own laptops** or if computers will be provided by the venue.

---

## **Dev Days [Your City]**

Join us for a community-led developer event focused on **AI-assisted coding with GitHub Copilot**.
This event brings together developers to explore practical workflows, real-world use cases, and hands-on experiences using GitHub Copilot.

Whether you are new to GitHub Copilot or already using it, this event will help you better understand how to apply AI-assisted coding techniques in everyday development.

---

## 🗓️ Event format

Choose the format that best fits your audience, available infrastructure, and time. This is flexible and you may customize the format.

### Sessions-only

* Technical sessions and demos
* Flexible agenda length

### Sessions + Workshop

* **Total duration: approximately 3 hours**
* Includes:

  * **1 technical session**
  * **1 hands-on workshop: App 60–90 minutes / Tailspin Toys CLI 120 minutes / Mona Mayhem CLI 60 minutes**

Choose one workshop and replace the agenda placeholders before publishing. For Tailspin Toys CLI, allocate 30 minutes for the talk, 120 minutes for the lab, and 30 minutes for setup, breaks, questions, and closing. Reserve at least 15 minutes within that buffer for setup or switching to CLI. If the lab runs over, finish one feature, verify it, and review the diff; leave extensions for later.

### Preparation to include in the attendee invitation

State the selected workshop, link its prerequisites from the [content guide](../content/README.md#-prerequisites), and ask participants to complete installation, login, and a test prompt before arrival. Confirm AI usage remaining, organization policies for both App and CLI, and Codespaces access/usage if needed. Share the [Japanese workshop texts](../website/ja/workshops/index.html) for the three current courses. Slides and videos remain in their original languages; state how these will be explained during the session.

UI changes may make screenshots differ from the installed App. Share the [Japanese CLI fallback guide](../website/ja/handson-guide.html) in advance. This private copy is served locally: distribute the repository to authorized participants or provide an approved handout; a localhost URL on the organizer's laptop is not an attendee URL. When copying this template into Luma, replace relative links with URLs or instructions participants can actually access.

> **Important**
> For events including a workshop, make sure the venue supports hands-on activities.
> This may include access to a **computer lab** (for example, at a university) or infrastructure for participants to use their **own laptops**, such as tables, **power outlets**, and a **stable Wi-Fi connection**.
