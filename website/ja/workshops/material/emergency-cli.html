教材セットの入口App シナリオの目次 事前準備・UI の確認

講師専用：CLI による緊急の作業保全・続行

この教材セット独自の運営・補助手順です。

App の演習を置き換える通常ルートではありません。まず App 内で現在の操作を確認し、解決できなければ App の講師デモまたはペア操作で学習を続けます。CLI は作業を失わず実装を続ける必要がある場合だけ使用し、その章の App 体験は未完了と記録します。

判断基準 · 作業場所と PR の確認

演習0の緊急対応：同じ演習コピーを準備する

この章は App・CLI 共通の準備です。本文の Tailspin Toys テンプレートから自分のコピーを作成し、そのコピーを clone します。すでに App が clone した場合は同じものを使い、新しいコピーを作らないでください。

Node.js 22.13以上、Git、CLI を準備します。npm を使う導入例です。

node --version
git --version
npm install -g @github/copilot
copilot --version

自分のコピーで README を確認して npm ci、npm run dev を実行し、表示された localhost URL をブラウザーで開きます。E2E を実行する場合は README に従い npx playwright install chromium も実行します。CLI の認証は次章で確認します。

合流条件： 自分のコピーが起動でき、remote が自分の repo を指していること。App のインストールが使えない場合も、CLI で本編を続けられます。App 機能の体験は未実施と記録します。

演習2の緊急対応：星評価を表示して最初の PR を作る

共通手順で同じ作業ブランチを開きます。未着手なら clean な既定ブランチから feature/app-02-rating などを作成します。CLI に引き継ぎ情報と次の要件を渡します。

Game 型と GameCard.astro、既存の差分を確認してください。
ホームページの各ゲームカードに既存の starRating（5点満点）を表示し、
null の場合は「No rating yet」と表示してください。
カードの構造は組み替えず、実装済みなら重複して追加しないでください。
数値と null のケースを検証し、quality-checks に従って確認してください。
commit・push・PR・merge はまだ行わないでください。

合流条件： 星評価と未評価の表示、関連テスト、レビューが完了していること。PR・合流の共通手順で自分のコピーに PR を作り、CI 確認後に通常マージします。最新の既定ブランチを取得して演習3へ進みます。

演習3の緊急対応：指示を更新し、コード例で確かめる

演習2の星評価がマージされた既定ブランチから、未使用の feature/app-03-instructions などで開始します。途中からなら既存ブランチを使います。自分のコピーの Update our repository coding standards Issue を確認し、本文を CLI へ渡します。Issue がなければ要件を講師と確認し、自分のコピーに作成します。

この Issue の要件に沿って .github/copilot-instructions.md を更新してください。
既存の指示を維持し、TSDoc の目的・引数・返り値とファイルヘッダーの標準を追加します。
最初に差分を読み、既に実装済みの部分は維持してください。PR はまだ作らないでください。

差分をレビューした後、次を依頼します。

ファイルは変更せず、すべての Publishers を返すライブラリコンポーネントの
コード例だけを示してください。更新した指示の TSDoc とヘッダーを反映してください。

合流条件： 指示ファイルと提示コードが要件に一致すること。ここでは CLI 独立コースのように publisher helper のファイルを作る必要はありません。リポジトリの品質確認後、共通手順で PR・マージを行います。演習4は星評価と指示が含まれる最新の既定ブランチから開始します。

演習4の緊急対応：同じフィルター機能を計画・実装する

演習2・3の変更を含む既定ブランチから feature/app-04-filtering などで開始します。App で着手済みなら、そのセッションの同じ worktree・ブランチを使います。自分のコピーのフィルター Issue 本文を貼り付け、/plan（利用できなければ通常の対話）で次を依頼します。

この Issue に従って、カテゴリーとパブリッシャーでゲームを絞り込む計画を作ってください。
星評価を維持し、既存の指示と差分を確認してください。
publisher helper が存在するとは仮定せず、現在の実装から必要な変更を判断してください。
選択方式、複数条件の意味、解除、該当なし、再読み込み時の状態を確認し、
受け入れ条件とテスト計画を示してください。まだ実装しないでください。

計画への質問に答え、内容を確認したら実装を依頼します。App の Autopilot を使えなくても、通常の CLI 対話で計画を承認し、必要な操作を許可して進められます。

確認した計画を実装し、.github/skills/quality-checks/SKILL.md を読んで
その手順で検証してください。スキルを読み込めたか、実行コマンド、結果、
未確認項目を報告してください。commit・push・PR・merge はまだ行わないでください。

合流条件： 要件に沿うフィルター、星評価の維持、新しいコードの指示準拠、quality-checks の成功と差分レビュー。スキルが呼び出せず同じコマンドを手動実行した場合は、スキル体験を未実施と記録します。演習5へは同じブランチ・未マージの機能を引き継ぎます。

演習5の緊急対応：同じフィルターを Playwright MCP で検証する

演習4の worktree・ブランチを維持します。別ターミナルで npm run dev を実行し、実際の URL を確認します。CLI の /mcp show で既存設定を確認し、なければ /mcp add で名前 playwright、種類 STDIO、コマンド npx @playwright/mcp@latest --headless を登録して保存します。

CLI と App の MCP 設定が共有されるとは仮定しません。接続できない場合、CLI の再起動とプロセス状態を確認します。Chrome がないエラーなら npx playwright install chrome を実行します。E2E 用 Chromium とは別です。Codespaces で sandbox エラーが出る場合に限り、CLI 参考資料の対処を確認してください。

Playwright MCP のブラウザーツールを使って [実際の localhost URL] を開き、
演習4で合意したフィルター条件、複合条件、解除、キーボード操作と星評価を確認してください。
期待値と実測値を記録し、不具合があれば修正して再検証してください。
MCP を使えない場合は成功扱いにせず、エラーを報告してください。PR はまだ作成しません。

合流条件： MCP ツール実行が確認でき、受け入れ条件を満たすこと。データによって0件が選べない場合はテストで補い、証拠を区別します。MCP が復旧しなければ通常のブラウザーとテストで機能を検証し、MCP は未実施と記録して演習6へ進みます。修正後は quality-checks を再実行します。

演習6の緊急対応：通常の PR レビューとマージ

Agent Merge 自体を CLI の通常操作で体験したことにはできません。この章は自分のコピーへの通常マージで統合を学び、Agent Merge は講師デモまたは後日実施とします。

  1. 演習4・5の同じ作業ブランチで差分と quality-checks の結果を確認します。
  2. PR・合流の共通手順で自分のコピーに PR を作成します。すでに PR があればその PR を更新します。
  3. base/head、差分、CI、レビュー指摘を確認します。失敗があれば同じブランチで修正・再検証し、PR を更新します。
  4. 自分のコピーへの通常マージを行い、最新の既定ブランチでフィルターと星評価が残っていることを確認します。

合流条件： PR の必要な CI とレビューが成功し、自分のコピーへ統合されていること。マージできなければ PR の状態と残作業を記録し、演習7では「すべてマージ済み」と仮定しません。Agent Merge の機能体験は別欄に記録します。

演習7の緊急対応：優先順位を文書で整理する

App の共有 Canvas・セッション開始ボタンを CLI で同等に再現する手順ではありません。ここでは優先順位の整理と共有可能な成果物の作成までを扱います。

自分のコピーの最新 Issue 一覧と PR の状態を確認し、取得できなければ本文を貼り付けます。未使用の作業ブランチを用意して次を依頼します。

この演習コピーの Issue から優先すべき3件を選び、理由と残りの一覧を
docs/workshop-triage.md に日本語で整理してください。既存ファイルがあれば維持して更新します。
Issue の URL、状態、優先理由、次の行動を含め、Issue 自体は変更しないでください。
App の Canvas を作ったという記述はしないでください。PR・merge はまだ行いません。

合流条件： 優先順位・理由・次の行動を説明できること。必要なら自分のコピーへの通常 PR で文書を共有します。Canvas の保存・共有・ボタン操作は講師デモまたは後日実施とし、未体験を記録して演習8へ進みます。

演習8の緊急対応：単発の振り返りと終了確認

App の Automation を使えない場合は、同じ要約を CLI で一度だけ実行します。予約・定期実行の代替ではありません。

この演習コピーで過去1週間にマージされた PR と、現在 open の Issue を要約してください。
取得できなければその旨を報告し、私が貼り付ける情報だけでまとめてください。
ファイル、Issue、PR は変更せず、定期実行も登録しないでください。

結果を自分の GitHub 表示と照合します。各章の成果・未確認項目・App 固有機能の体験を振り返り、開発サーバーと CLI を停止します。Codespace を使用した場合は自分の演習環境を停止し、作成した定期実行があれば不要なものを停止します。PR と未保存の作業は残します。

合流条件： 実際の履歴に沿う振り返りと終了確認。Automation 体験は単発要約と区別して記録します。章別検証表を参照してください。
