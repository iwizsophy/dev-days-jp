講師専用：緊急対応時の作業保全・PR・復帰

この教材セット独自の運営・補助手順です。

本編は App の演習0〜8です。このページは講師の緊急対応用で、本編の通常経路ではありません。CLI 独立コースを最初から実施する必要はありません。教材サイトの dev-days-jp と、コードを改修する自分の Tailspin Toys コピーを区別してください。以下の Git・npm・Copilot コマンドは、自分の演習コピーで実行します。

切り替える前に

  1. App の実行中エージェントを停止し、編集内容を保存します。
  2. App セッションの作業ディレクトリを確認します。worktree は元の clone と別の場所です。クラウドセッションの場合は、作業を自分のリモートブランチへ保存して取得してから続行します。場所やブランチが不明なら講師と確認します。
  3. 同じ作業場所のターミナルで次を実行し、対象、ブランチ、差分を照合します。
git rev-parse --show-toplevel
git remote -v
git branch --show-current
git status --short
git diff --stat

remote が自分の演習コピーでない場合は停止します。参照元の github/dev-days、github-samples/copilot-workshops、github-samples/tailspin-toys に push・PR・Issue を送ってはいけません。既存のブランチなら作り直さず続行します。未着手で、既定ブランチが clean の場合だけ、章に応じた未使用名で git switch -c feature/app-02-rating のように作成します。

同じ課題を引き継ぐ

copilot を起動します。通常の対話で進め、変更・実行の許可は内容を確認します。App の会話は自動で引き継がれるとは限りません。次の角括弧を埋め、続いて各章のプロンプトを入力してください。

App シナリオの演習[番号]を、この作業ディレクトリで続けます。
対象は自分の演習リポジトリ[owner/repo]とブランチ[名前]だけです。
要件：[自分の Issue URL と本文、または章の要件]
実装済み：[内容]。止まった点：[内容]。
README、CONTRIBUTING、指示ファイル、既存の差分を読んでください。
まだ変更せず、残りの計画と検証方法を日本語で示してください。
参照元リポジトリへの書き込みは禁止です。
commit・push・PR・merge は個別に依頼するまで実行しないでください。

Issue の番号はコピーにより変わります。自分のリポジトリでタイトルと本文を確認し、取得できなければ本文を貼り付けます。必要な Issue がなければ、このコピー内だけに作成します。

品質確認から PR へ

章の確認に加え、.github/skills/quality-checks/SKILL.md と README に従って関連テスト・lint・型チェックを実行します。失敗を修正して再確認し、差分をレビューします。端末のシェルコマンドは CLI を終了するか、別ターミナルで実行してください。

  1. git diff と git status --short を確認し、対象のソース・テスト・文書だけをステージします。MCP の一時出力や認証情報を含めません。
  2. git diff --cached を確認して commit します。
  3. push 先が自分のコピーで、現在のブランチが main ではないことを再確認します。git push -u origin HEAD で同名ブランチへ送ります。
  4. GitHub で 自分のコピーを base repository とする PR を作成します。base はそのコピーの既定ブランチ、head は作業ブランチです。要件・差分・テスト結果・未確認事項を本文に記録します。
  5. PR の差分と必要な CI を確認します。演習2・3はレビュー後に自分のコピーへ通常マージして次へ進みます。演習4・5は同じブランチを維持し、演習6でマージします。

PR の作成先やマージ先に参照元が表示された場合は操作を止め、base repository を確認し直してください。

次の章と App への復帰

演習2・3のマージ後は、元の clone など既定ブランチを所有する作業ディレクトリで git fetch origin、既定ブランチへ切り替え、git pull --ff-only を実行します。別 worktree で同じブランチが使用中なら、その worktree で更新します。未保存の作業を reset・clean で消してはいけません。

App 操作の再開を優先します。App に戻る場合は CLI のエージェントを終了し、同じ作業ディレクトリとブランチを開き、変更とテスト結果を伝えます。開けない場合は App 操作を未完了とし、講師デモまたは後日実施へ切り替えます。演習4〜6の途中では、新しいセッションを既定ブランチから始め直さないでください。

App 固有の Agent Merge・Canvas・Automation は、通常の PR や Markdown、単発実行で代用しても機能体験は未実施です。実装の到達点と App 機能の体験を別々に記録します。
