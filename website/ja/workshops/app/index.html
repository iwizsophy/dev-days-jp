この教材セットの進め方

本教材は、GitHub Copilot App を使った開発フローと操作体験を一連の流れで学ぶ本編コース です。演習 0〜8 を順番に進めます。

単にコードを完成させることだけが目的ではありません。次のような App の機能を、実際に手を動かして体験・確認します。

  • エージェントセッションの立ち上げと管理
  • 生成されたコードの差分レビュー
  • MCP（Model Context Protocol）による外部ツール連携
  • Agent Merge による Pull Request の自動マージ
  • キャンバスを使った設計・タスク整理
  • Automation による定型作業の自動化

この演習で身につける判断

題材となるTailspin Toysは、ゲームを紹介するクラウドファンディングサイトです。利用者が支援したいゲームを探せるように、カードの星評価、カテゴリーとパブリッシャーによる絞り込み、タイトル検索を順に追加します。前の章で作った機能を残したまま次の変更を加えるため、既存の振る舞いを確かめることも各章の課題になります。

この順番には学習上の理由があります。最初は小さな星評価の変更を通じて、要件を伝え、差分を読み、テストと画面を確認してからマージする一連の判断を経験します。その後、指示ファイルで共通の前提を共有し、Planで仕様の曖昧さを解消してから、自律的な実装へ進みます。人が確認する観点を理解したうえで、Agent MergeやAutomationに任せる範囲を広げます。

各章では「何ができたか」に加えて、「なぜその方法を選んだか」を説明できることを目指してください。

学ぶ判断 演習で確かめること
依頼する範囲を決める Issueの要件、変更してよい範囲、作業を止める位置を伝える
必要な前提を共有する 会話だけでなく、指示ファイル・スキル・Issue本文を使い分ける
結果を根拠で評価する 応答の「完了」と、差分・テスト・実際の画面・CIの結果を照合する
自動化の範囲を決める 人が承認する仕様と、エージェントに任せる繰り返し作業を区別する

本文のプロンプトは、これらの判断を練習するための出発点です。出力されるコードやテスト件数は毎回同じとは限りません。期待した結果と違う場合は、違いを具体的に伝えて修正を依頼し、再度確認してください。公式にも、変更をレビューし、フィードバックを返して改善する流れが示されています。出典：GitHub Copilot Appの開発フロー。

画面画像と操作手順の注意点

GitHub Copilot Appは最新版を使用してください。

  • 掲載画像について：画像は操作位置の参考です。画面が異なる場合は、本文の操作対象と項目名を確認してください。検索機能や並べ替えIssueを使った画像は、各章の実装結果そのものではありません。
  • UI が異なる場合：操作ボタンが見当たらない場合は、本文の操作対象と項目名を確認し、講師に相談してください。
  • リポジトリの分離：演習は教材用テンプレートの Use this template から各自が作成したTailspin Toysのコピーで行います。演習先を間違えないよう、セッション開始時とPR作成時に所有者とリポジトリ名を確認してください。参照元リポジトリへのpush、Pull Request、Issue作成は行いません。

GitHub Copilot App の概要

GitHub Copilot app は、Copilot CLI を基盤とするデスクトップアプリケーションです。エージェント主導の開発環境をひとつのワークスペースに統合します。

主な特徴と機能：

  • 並列エージェントセッション：独立した複数の作業を同時に進行
  • セッションモードの切り替え：計画立案（Plan）や自律実装（Autopilot）を用途に応じて選択
  • GitHub ネイティブ管理：Issue や Pull Request をアプリ内で直接操作
  • Agent Merge：許可した範囲でレビュー指摘やCI失敗への対応、競合の解消、マージを進める
  • 共有キャンバス：アイデアやタスクを視覚的に整理

本コースでは、アプリの導入と演習用リポジトリの接続から始め、バックログに用意された Issue に沿って開発を進めます。

  1. 星評価の追加：小さな機能改修を通じて、セッション開始から PR 作成・マージまでの基本サイクルを体験
  2. カスタム指示の標準化：コーディング規約やドキュメント標準を指示ファイルに定義し、プロジェクトへ反映
  3. フィルター機能の自律実装：Plan モードと Autopilot モードを使い分け、スキルを活用して品質を検証
  4. 外部ツール連携（MCP）：Playwright MCPの接続とツール実行を確認し、エージェントが実際のブラウザーを操作して動作を検証
  5. 段階的マージの自動化：レビューと許可範囲を確認し、Agent Merge にPRの修正やマージを任せる
  6. 協調作業と自動化：共有キャンバスでタスクを整理し、繰り返し発生する作業を Automation で自動化

アイデアの具体化から機能のマージに至る、AI 支援開発の包括的なライフサイクルを体験できます。

機能の概要はGitHub公式のApp紹介、モードごとの役割はセッションモードの説明を参照してください。本文では、その機能をTailspin Toysのどの課題に使い、どこで人が判断するかを具体的に扱います。

前提条件

ワークショップに参加する前に、次の環境を用意してください。

  • GitHub アカウント：有効な Copilot プラン（Free を含む）が設定されていること。全演習を完走するのに十分な利用枠があるか事前に確認してください。
  • PC 環境：macOS、Linux、Windows のいずれかが動作すること。
  • Git：PC にインストール済みであること。

ヒント 有料プランを利用していない場合でも、認証済みの学生は GitHub Education を通じて GitHub Copilot を無料で利用できます。Copilot Student プランには、本ワークショップで使用するエージェント、MCP、コードレビュー、Copilot CLI の各機能が含まれています（演習の完走に必要な利用枠は別途確認してください）。

補足 Copilot app はクラウド上の Codespaces ではなくローカル PC 上で直接実行します。そのため、レッスン 0 ではアプリをインストールする前に Node.js をインストールし、プロジェクトの演習用コピーを準備します。

補足 Copilot Business または Copilot Enterprise を利用している組織では、アプリを使用するために組織管理者が GitHub Copilot app ポリシー（CLI のポリシーとは別個）を有効化している必要があります。

利用条件はAppの利用可能範囲とCopilotプランの公式案内を参照してください。参加前に、使用するアカウントで接続できることと、利用枠や組織のポリシーを確認します。
