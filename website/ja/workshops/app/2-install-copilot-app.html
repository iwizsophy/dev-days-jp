2.1 章の概要

GitHub Copilot appでは、課題を読む操作、エージェントに相談する操作、コードの実装を進める操作を使い分けます。この章では、Appに接続するリポジトリと表示条件を確かめ、目的に合った作業場所を選ぶ方法を学びます。

課題が画面に見当たらないとき、課題自体がないのでしょうか。それとも表示条件によって隠れているのでしょうか。対象のリポジトリと表示条件を確認できれば、自分の課題を選んで作業を始められます。

2.1.1 この章で学ぶこと

項番 この章で行うこと 到達した状態
1 Appをインストールしてサインインし、演習用リポジトリを追加する Appで自分のアカウントと演習用リポジトリを確認できる
2 リポジトリの起動コマンドと設定を読み、内容を確認して承認する エージェントが使う起動コマンドや設定を把握し、承認した内容を説明できる
3 対象のリポジトリと表示条件を確かめ、Issueの背景と受け入れ条件を読む 課題の有無と表示条件の影響を区別し、取り組む課題を選べる
4 Chatsでworktreeの仕組みを質問し、回答を読む コードを変更する前に、疑問や考えをChatsで整理できる

2.2 取り組む前に

前章で作成したTailspin Toysの演習用リポジトリのowner/repoを用意してください。Appには、そのリポジトリを利用できるGitHubアカウントでサインインします。

利用するGitHubアカウントのCopilotプランが有効であることと、演習に必要な利用枠を確認してください。公式ドキュメントでは全Copilotプランが対象です。Copilot BusinessまたはCopilot Enterpriseの組織では、CLI用とは別のGitHub Copilot appポリシーが有効である必要があります。利用条件は公式の概要、Gitのインストールなどの前提は公式の開始手順を参照してください。

GitHub Copilot appは最新版を使用します。すでにインストールしている場合は更新してから始めます。

2.3 ケース

この章でGitHub Copilot appに接続するのは、第1章で準備したTailspin Toysの演習用リポジトリです。接続後は、Issuesで演習用の課題を読み、相談用のChatsでworktreeの仕組みを質問します。

項番 観点 このケースで扱う内容
1 状況 Node.jsと自分用の演習リポジトリは準備済みです。次章でゲームカードの星評価を変更する前に、Appからそのリポジトリを扱えるようにします。
2 課題と理由 実装を始めるには、Appで課題を読む場所、相談する場所、コードを変更する場所を確かめる必要があります。Issuesに課題が表示されない場合も、課題がないと決めず、対象リポジトリと表示条件を確認します。
3 解決策 Appを導入してGitHubアカウントでサインインし、演習用リポジトリを接続します。利用する設定を読んで承認したうえでIssuesの課題を表示し、Chatsでコードを変更しない相談を体験します。

2.3.1 Appをインストールしてサインインする

GitHub Copilot appのインストーラーの対象OSは、Windows、macOS、Linuxです。自分のOSに合わせて進めてください。

  1. GitHub Copilot appのダウンロードページを開きます。
  2. 使用するOS向けの最新版をダウンロードし、画面の案内に従ってインストールします。
  3. Appを起動し、Sign in to GitHubを選択します。ブラウザーが開いたら認証を完了させます。
  4. Connect your repositoriesが表示されたら、ここでは選択せずに進みます。この教材では、初期設定後に演習用リポジトリを追加します。
  5. Continueを選択します。テーマの選択画面が表示されたら、好みのテーマを選び、Finishで初期設定を終えます。

2.3.2 演習用リポジトリを接続する

演習用リポジトリをAppへ接続する前に、Appの利用アカウントと、そのリポジトリの所有者を確認します。AppのRepository trustでは、リポジトリ内の設定や拡張を新しいセッションで利用するか判断します。どの設定を使うか、内容を読んでから承認しましょう。

  1. サイドバーのProjects横の+ → Add GitHub repositoryを選びます。
  2. 前章で控えた自分のowner/repoを検索して追加します。
  3. Review repository contentが表示されたら、設定や拡張を開いて内容を確認します。教材用のTailspin Toysテンプレートには、後の演習で使う起動コマンドやMCPの設定が含まれています。
  4. Repository trustで対象が自分のコピーであることと、承認する内容を確認し、Accept for new sessionsを選択します。

  1. 追加した演習用プロジェクトの入力欄へ進めたことを確認します。準備中の表示がある場合は完了を待ちます。実装用の新しいworktreeは次章で開始します。

演習用プロジェクトの入力欄が表示されない場合や、AppとGitHubの連携でエラーが出る場合は、対象リポジトリ、承認状態、サインインしたアカウントを確認してください。必要に応じて講師と確認します。

2.3.3 対象と表示条件を確かめてIssueを読む

AppのProjectsでプロジェクトを選ぶことと、Issuesの表示対象を選ぶことは別の操作です。Issues上部の対象リポジトリを確認して、接続した演習用リポジトリの課題を表示します。

  1. サイドバーのIssuesを開きます。
  2. 画面上部のリポジトリ選択欄で、自分の演習用コピーだけを選択します。他のリポジトリが選ばれている場合は解除します。
  3. 表示条件を確認します。演習用リポジトリに自動生成された課題は未割り当てなので、Assigned to meでは表示されません。Nothing hereと表示される場合は、タブ右の+ → New viewを選択します。
  4. State: Open、追加の検索条件なしでSaveします。New viewの入口が見えない場合は、右側のIssue詳細を閉じてから操作してください。

  1. 8件の課題が表示されることを確認します。後の演習では、次の課題を使います。
項番 Issueのタイトル 取り組む内容
1 Update our repository coding standards コーディング規約とドキュメント標準
2 Allow users to filter games by category and publisher フィルター機能
3 Add a search box to find games by title タイトル検索
  1. 任意のIssueを開き、背景と受け入れ条件を読みます。この章では内容を確認し、実装は後の章で始めます。

AppのIssues一覧が空だった場合は、表示条件を変えた前後を比べてください。リポジトリが選べない場合は、接続手順を見直します。GitHub Webの演習用リポジトリにも課題がない場合は、前章のIssue準備を確認します。

2.3.4 Chatsで質問する

GitHub Copilot appのChatsは、ブランチやworktreeを作らずに、エージェントに質問したりアイデアを相談したりする機能です。会話の履歴を保存して、後から読み返せます。ここではAppの仕組みについて相談します。

  1. サイドバーのChatsを右クリックし、New chatを選択します。
  2. 入力欄の下で対象がChat、モードがInteractiveであることを確認します。
  3. 次のプロンプトを入力して送信します。
GitHub Copilot app は worktree をどのように使いますか？
日本語で簡潔に説明してください。説明だけを行い、ファイル変更、
リポジトリ操作、コマンド実行はしないでください。
  1. 日本語の回答を読み、処理終了後にステータスがIdleへ戻ることを確認します。
  2. 回答の中で「別の作業フォルダー」「ブランチ」「マージ」がどのようにつながるか、読み取ってみましょう。分からない点は同じチャットで質問します。

Chatsで受け取る回答は、エージェントによる説明です。次章ではTailspin Toysの実装セッションの作業場所を確認し、この回答と実際の動作を比べます。相談用のChatsと実装セッションの違いはGitHub公式のセッション説明も参照してください。

2.4 結果の整理と振り返り

GitHub Copilot appを導入し、演習用リポジトリの課題を読んだり、エージェントに相談したりする準備ができました。次の状態を確認してください。

  • 自分のGitHubアカウントでサインインし、演習用コピーを接続できた。
  • 設定を読んで承認し、Issuesにコピーの8件の課題を表示できた。
  • Chatsで質問し、回答を読み返せる状態になった。

「Assigned to meが空でも課題がないとは限らない理由」と「Chatsでの相談と実装セッションの違い」を説明してみましょう。設定の承認では何を確認したかも振り返ると、次章で作業対象を確かめてから編集を始められます。

次章では、演習用サイトTailspin Toysのゲームカードに星評価を表示する変更をエージェントに依頼します。第3章「最初のエージェントセッションの実行」へ進んでください。

2.5 補足

2.5.1 Appとworktreeの役割

GitHub Copilot appは、エージェントによる開発を進めるデスクトップアプリケーションです。GitHub Copilot CLIを基盤とし、リポジトリ、ブランチ、CIと連携します。Issueの選定から実装依頼、差分のレビュー、PRの作成とマージまでをまとめて扱えます。

Appで実装セッションを始めるときは、新しいworktreeなどの実行場所を選んでください。worktreeは、同じリポジトリの別ブランチを別の作業フォルダーで扱う仕組みです。Tailspin Toysの星評価とフィルターを別々に試す場合も、作業中のファイルを分けられます。ただし、完了した変更を次の作業で使うには、PRをマージした状態を次のセッションに引き継ぐ必要があります。各章で結果を確かめてから、次の機能へ進んでください。実行場所の選択肢は公式のセッション開始手順を参照してください。

2.5.2 作業領域を使い分ける

項番 領域 主な役割
1 Projects プロジェクトと実装セッションを管理する
2 Chats 作業ツリーやブランチを作らずに相談する
3 Issues 対象リポジトリの課題を検索し、実装を始める
4 Pull requests 差分やCI結果を確認し、変更を取り込む
5 Automations 手動やスケジュールで実行する自動化タスクを管理する。第9章で使う
6 Customize MCP、Plugins、Skills、Extensionsなどの設定やInstalledを開く

Appで相談するときはChats、コードを変更するときはProjectsのセッション、変更をリポジトリへ取り込む前の確認にはPull requestsを使います。GitHubと連携する一覧の役割は公式のIssue・PR管理手順も参照できます。

演習用リポジトリの接続時に設定画面を通過したことと、Tailspin Toysのビルドやテストが成功したことは別です。エージェントによる実装後は、コードの差分、画面、検査結果をそれぞれ確認します。

2.5.3 会話を整理するメニュー

AppのChats一覧で完了したチャットを右クリックすると、名前の変更やアーカイブなどの操作を確認できます。メニューの項目を読み、会話を整理する方法を確かめてみましょう。この演習ではメニューの確認までとし、共有や削除は行いません。
