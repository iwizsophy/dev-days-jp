1.1 章の概要

この教材では、ゲームを紹介するクラウドファンディングサイト「Tailspin Toys」を題材に、GitHub Copilot appのエージェントと開発を進めます。体験するのは、変更の目的を伝え、生成されたコードとテストを確認し、レビューした変更を自分のリポジトリへ取り込む流れです。

最初に、アプリのビルドとテストを動かすNode.jsと、自分で変更できる演習用リポジトリを準備します。環境の準備ができていれば、後の章でエラーが起きたときも、環境と実装を分けて調べやすくなります。

1.2 この章で学ぶこと

到達した状態 後の演習でできること
実行されるNode.jsのバージョンを確認できる ビルドやテストに必要な環境がそろっているか判断する
テンプレートから自分のコピーを作成できる Issue、ブランチ、Pull Requestを使って変更を管理する
演習用Issueが用意されたことを確認できる 課題の背景と受け入れ条件を読んで実装を依頼する

1.3 取り組む前に

ブラウザーでGitHubにサインインし、自分のアカウントでリポジトリを作成できる状態にしてください。ローカルPCでは、普段使っているターミナルを開けることを確認します。

本教材ではNode.js 24系のLTS版、24.19.0以降を使用します。すでにこの条件を満たしていれば、再インストールは不要です。nvmなどでバージョンを管理している場合は、その管理方法に合わせて切り替えます。

演習に使うのは、教材用のTailspin Toysテンプレートです。使用する教材のバージョンはv2026.10.03で、星評価やフィルター機能の解答コードは含まれていません。教材リポジトリのdev-days-jpと、これからコードを変更するTailspin Toysのコピーを区別して進めます。

1.4 体験すること

1.4.1 Node.jsのバージョンを確認する

インストール済みのバージョンと、今のターミナルが実行するバージョンは一致するでしょうか。まずコマンドの出力を調べます。

  1. Windows Terminal、macOS Terminalなど、普段使うターミナルを開きます。
  2. 次のコマンドを実行します。
node --version
  1. Node.js 24系の24.19.0以降が表示されたら、演習用リポジトリの作成へ進みます。コマンドが見つからない場合や、条件を満たさない場合は、次の手順で準備します。

1.4.1.1 インストールが必要な場合

  1. Node.jsのダウンロードページを開きます。
  2. 使用するOSに合わせて、Node.js 24系のLTS版、24.19.0以降をダウンロードします。
  3. インストーラーを起動し、既定の設定で進めます。Windowsでは、Add to PATHが有効であることを確認してください。
  4. インストール後、新しいターミナルを開き直します。
  5. もう一度node --versionを実行し、条件を満たすバージョンが表示されることを確認します。

すでにCopilot Appを起動している場合は、完全に終了して再起動します。新しい環境変数を反映したうえで、実装セッションでもNode.jsを確認してください。確認方法は、第3章の実装前の環境確認で扱います。

1.4.2 テンプレートから演習用リポジトリを作る

後の章では、自分のコピーでIssueやPull Requestを扱います。コピーを作る前に、元のテンプレートとコピー先の所有者を確認しましょう。操作の詳細はGitHub公式のテンプレートからの作成手順も参照できます。

  1. ブラウザーでhttps://github.com/iwizsophy/dev-days-tailspin-templateを開きます。
  2. Use this template → Create a new repositoryを選択します。

  1. 作成フォームで次の項目を設定します。
項目 設定する内容
Start with a template iwizsophy/dev-days-tailspin-templateであることを確認する
Include all branches 既定のOff、チェックなしのままにする
Owner 自分のアカウントまたは演習用Organizationを選ぶ
Repository name 自分の演習用の名前を入力する。例はdev-days-tailspin-toys
Choose visibility 演習用リポジトリの公開範囲を選ぶ

  1. フォーム下部の任意項目Jumpstart your project with Copilotでは、Prompt欄を空欄のままにします。
  2. 入力内容を確認し、Create repositoryを選択します。
  3. 作成したリポジトリのowner/repoを控えます。次章ではこのコピーをAppに接続します。

1.4.3 演習用Issueを確認する

コピーの作成後に自動実行されるのが、GitHub ActionsのBootstrap template issuesワークフローです。実行が終わると、演習で使う8件のIssueが作成されます。

  1. 作成したコピーのIssuesタブを開き、8件の課題が表示されることを確認します。
  2. 課題が表示されない場合は、同じコピーのActionsタブで実行状況を確認します。
  3. 必要に応じてBootstrap template issues → Run workflowを実行し、終了後にIssuesを開き直します。

Issueのタイトルには、フィルター機能やコーディング規約など、これから取り組む変更が表れています。コードのコピーと課題の準備がそろったことを確認して、次へ進んでください。

1.5 結果の整理と振り返り

Node.jsと、自分で変更できる演習用リポジトリを用意しました。次の項目を確認してください。

  • node --versionで、Node.js 24系の24.19.0以降を確認できた。
  • テンプレートから自分のコピーを作成し、owner/repoを控えた。
  • コピーのIssuesに、演習用の8件の課題が表示された。

「各自のコピーが必要な理由」と「インストール後にバージョンを確認する理由」を、自分の言葉で説明してみましょう。予想したバージョンと実際の出力が違った場合は、何を切り替えて解決したかも振り返ります。

次はAppをインストールし、コピーを接続します。第2章「GitHub Copilot appのインストール」へ進んでください。

1.6 補足

1.6.1 この教材で体験する開発の流れ

GitHub Copilot appは、エージェントの作業とGitHubのリポジトリ管理をまとめて扱うデスクトップアプリケーションです。Issueから実装を始め、差分やテスト結果を読み、Pull Requestを通じて変更を取り込めます。機能の全体像はGitHub公式の説明で確認できます。

この教材で変更の目的と確認条件を伝えるのは受講者です。エージェントの完了報告を受けた後も、実際のコードや画面を確認し、必要なら修正を依頼します。環境を準備する段階から、説明と実際の結果を照合する習慣をつけましょう。

1.6.2 Node.jsと実行環境

Tailspin ToysはAstroで構築されています。ローカルPCのNode.jsでアプリをビルドし、Vitestの単体テストとPlaywrightのE2Eテストを実行します。

ターミナルで確認できるのは、そのターミナルが使うNode.jsです。Appの実装セッションで使うバージョンも確認すると、要件との違いを見つけられます。バージョン管理ツールを使っている場合も、コマンドの出力を確かめてください。インストールの完了と、実行されるバージョンの確認は別の作業です。

テンプレートにはdev containerの設定もあります。Docker Desktopなどで別の環境を使う場合は、講師の案内に従ってください。

1.6.3 各自の演習用コピーを使う理由

Issueを起点に実装し、レビューした変更を自分のmainへ取り込むため、各自の演習用コピーを作ります。他の受講者の作業と分けて進められ、試した変更の履歴も自分で確認できます。

テンプレートからの作成は、用意されたファイルを基に新しいプロジェクトを始める操作です。詳細はGitHub公式のテンプレート説明を参照してください。
