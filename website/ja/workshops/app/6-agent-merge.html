シナリオ

本ワークショップを通じて、コード生成、自動テスト、MCP による実ブラウザー操作と、段階的に自動化のレベルを引き上げてきました。Tailspin Toys では開発速度をさらに向上させるため、検証済みの pull request に対する機械的なマージ待機と最終処理を自動化する手法を検討しています。

Agent Merge の概要

Agent Merge は、pull request の作成からマージ完了までの最終工程をエージェントに自律実行させる機能です。

Agent Merge を有効にすると、エージェントは PR の状態を常時監視し、以下のようなマージを妨げる障害が発生した場合に自律的に対処を試みます。 - CI チェック失敗時の原因調査と修正コードのプッシュ - レビューコメントへの対応 - main ブランチとの競合（コンフリクト）発生時のリベースや解消作業

そして GitHub 上でマージ条件が満たされ次第、エージェント自身が pull request を自動マージします。この処理はバックグラウンドで動作し、アプリを再起動してもタスクは継続され、マージが完了すると自動的に終了します。

これまでの手動マージでは、人間が CI の完了を待ってボタンを押す必要がありました。Agent Merge を活用することで、人間は「コードのレビューと承認」という本質的な判断に専念し、承認後の機械的な待機や後処理をエージェントに委託して即座に次のタスクへ着手できるようになります。

Agent Merge で PR を管理する

コードレビュー、自動テスト、UI 検証を終えたフィルター機能のコードをマージしましょう。Agent Merge を起動し、CI 監視からマージまでをエージェントに任せます。

  1. 前章まで作業していたフィルター機能の実装セッションを開きます。
  2. 画面右上にある Create PR ボタンの右側にあるドロップダウン矢印を選択します。
  3. メニューから Agent merge を選択します。


実機撮影：2026-09-13、Windows、GitHub Copilot App 1.1.20。撮影範囲全体を掲載（切り抜きなし）。灰色の箇所はアカウント・検証用リポジトリ・ローカルパス等の識別情報や個人の利用量をマスク。Agent merge・Create PR・Create draft PR の選択メニュー。検索機能の PR 作成前の操作例。

  1. ボタンの表示が Agent merge に切り替わります。
  2. Agent merge ボタンをクリックし、マージの自律プロセスを開始します。

エージェントが pull request の作成と管理を開始します。まずリポジトリの状況を分析して最適な PR を起票します。PR 作成後、エージェントは CI ワークフローの実行状態やレビューステータスを監視します。

  1. Agent merge ボタン横のドロップダウンを再度開き、Merge pull request のチェックボックスを確認します。
    もし未選択になっている場合は、クリックしてチェックを入れてマージ権限を許可してください（すでにチェックが付いている場合はそのままにします。再度クリックすると許可が解除されてしまうため注意してください）。

  1. リポジトリ上の全 CI プロセス（テスト、lint、ビルド等）が正常に完了すると、Copilot が pull request を自動的にマージします。

実機検証における確認記録と注意点

2026年9月13日の実走検証では、次の挙動を確認しました。 - PR の自動起票：手順 5 の実行によって PR #12 が自動起票されました。 - マージ権限の設定：手順 6 のドロップダウンメニューを確認したところ、初期状態では「Address reviews」「Fix CI failures」「Resolve conflicts」の 3 項目は有効化されていましたが、「Merge pull request」は無効（チェックなし）になっていました。 - 自動マージの成功：手動で「Merge pull request」にチェックを入れたところ、CI の全 4 ジョブが正常通過した直後に自動マージが実行され、App セッション画面および GitHub の Web 画面の双方でステータスが Merged に更新されました。 - 未検証範囲：本実走では CI が一発で成功し競合も発生しなかったため、CI 失敗時の自動修正やコンフリクト解消の自律挙動については実機未検証です。

次章へ進む前に、新しく作成する worktree にこのフィルター機能のマージ結果が正しく継承されていることを確認してください。
