ここまでは、チャットを通じてエージェントを指示してきました。しかし、多くの作業は会話の中ではなく、ボード、ドキュメント、チェックリスト上で行われます。キャンバスは、まさにそのような作業のために、アプリ内でユーザーとエージェントが共有できる領域です。このレッスンでは、ここまで取り組んできたバックログの計画と追跡に使用する、シンプルなキャンバスを作成します。

このレッスンでは、次の内容を学習します。

  • キャンバスの概要と使用する場面を理解する。
  • バックログをトリアージする共有 Kanban ボードのキャンバスを作成する。
  • キャンバスをリポジトリに保存し、チーム向けにマージする。
  • 新しいセッションでキャンバスを開き、そこから作業を開始する。

シナリオ

Issue の一覧は、どのような状況でも負担に感じることがあります。Tailspin Toys の開発者は、Issue をすばやくトリアージし、Copilot app で作業を開始できるツールを探しています。

キャンバスとは

キャンバスは、計画、トリアージボード、リリースチェックリスト、ダッシュボード、ドキュメントなどの作業成果物を扱う、共有の対話型領域です。チャットは意図の説明や曖昧さの検討に適していますが、多くの作業は具体的な領域上で行われます。キャンバスを使うと、その領域でエージェントと直接共同作業できます。

キャンバスは双方向です。エージェントが作業中にキャンバスを更新できる一方で、ユーザーも同じ領域を編集できます。キャンバスを作成すると、エージェントはプロンプトとワークフローに基づいて内容を構築します。その後も、機能の追加、削除、修正を依頼できます。作成したキャンバスは、アプリの右側のパネルに開きます。

一般的な例は次のとおりです。

  • 1日の計画を立て、Issue と pull request に優先順位を付けるための Markdown canvases。
  • ユーザーとエージェントがカードを追加し、作業を列間で移動する Agentic kanban boards。
  • リポジトリの重要な Issue と繰り返し現れるテーマをまとめる Issue triage boards。

キャンバスを使用する理由

タスクに構造、反復、検証が必要で、チャットだけでは不十分な場合はキャンバスを使用します。キャンバスでは次のことができます。

  • ワークフローに合った実際の成果物に、エージェントの作業を結び付ける。
  • 共有領域で作業を直接調整または修正し、その変更を基にエージェントに作業を続けさせる。
  • チャットの応答だけでなく、成果物への目に見える変更として進捗を確認する。

作業を追跡するキャンバスを作成する

星評価、ドキュメント標準、フィルター機能をすべてマージし、多くの成果をリリースしました。しかし、バックログにはまだ項目が残っています。作業をすばやくトリアージするためのキャンバスを作成します。

  1. GitHub Copilot app に戻ります。アプリを閉じている場合は開きます。
  2. サイドバーで自分の演習リポジトリの横にある New session を選択します。App 1.1.20 の実走では New 画面が開きました。
  3. 入力欄の下で自分の演習リポジトリ、New worktree、main が選択されていることを確認します。作成後の worktree に前章のマージ結果が入っていることも確認します。
  4. プロンプトボックスで次のプロンプトを使用し、要件を満たすキャンバスを作成します。
作業の優先順位をすぐに整理できる、基本的なカンバンボードの canvas を作ってください。今対応すべき上位3件の Issue を強調し、残りは下の別の領域に配置してください。上位3枚のカードには Issue の内容と優先する理由を含めてください。各 Issue に、現在のセッションのコンテキストへ追加してすぐ作業を始められるボタンを付けてください。

Copilot がキャンバスの作成を開始します。

実走では Issue triage board が右パネルに開き、未対応6件を上位3件と残り3件に分けて表示しました。初版は上位3件にしかボタンがなかったため、全カードに Add to current session を付けるよう追加依頼しました。表示だけで完了にせず、カード数・優先理由・更新ボタンと各カードの操作を確認してください。

補足 作成には数分かかります。複雑なタスクであるため、最初のバージョンでは満足できない場合があります。理想のツールになるまで、プロンプトで構築を続けるよう依頼できます。

キャンバスを保存してリポジトリにマージする

キャンバスは、指示ファイルやスキルと同様に、リポジトリのアセットにできます。Copilot にリポジトリへの追加とマージを依頼し、チーム全体で使用できるようにします。

  1. 同じセッションで、次のプロンプトを使ってキャンバスをリポジトリに保存するよう Copilot に依頼します。
開発チームと共有できるよう、この canvas の定義をリポジトリに保存してください。
  1. Copilot がキャンバスファイルを保存したら、右上隅にある Create PR の横のドロップダウンを選択します。

保存場所も確認します。実走の初版はセッション限定で、共有依頼後に .github/extensions/issue-triage-board/extension.mjs と README の起動手順を追加しました。これは公式のプロジェクト共有スコープです。セッション一時フォルダーにしかない状態では、チーム共有や別セッションでの再利用を確認したことにはなりません。すでにボタンが Agent merge なら手順5へ進みます。 3. Agent merge を選択して Agent Merge を有効にします。


参照元の画面例（撮影時バージョン不明・現行 UI 未照合）。位置やメニューの開き方は講師と確認してください。

  1. ボタンのテキストが Agent merge に変わります。
  2. Agent merge ボタンを選択し、Agent Merge のプロセスを開始します。

Copilot app が PR の作成と管理を開始します。最初にプロジェクトを調査して PR の最適な作成方法を判断し、PR を作成します。

しばらくすると、Copilot が再び作業を開始し、リポジトリ上ですべてのテストを実行する CI プロセスなど、PR の条件を確認します。ほかのチームメンバーによるレビュー、実行が必要なチェック (CI プロセス)、PR をマージできるかどうかのステータスを報告します。

  1. Agent merge の横にあるドロップダウンを選択してから Merge pull request を選択し、Agent Merge に pull request のマージを許可します。


参照元の画面例（撮影時バージョン不明・現行 UI 未照合）。位置やメニューの開き方は講師と確認してください。

  1. すべての CI プロセスが成功するまで待ちます。成功すると、Copilot が pull request を自動的にマージします。

これでチーム用の新しい共有キャンバスを作成できました。

キャンバスで作業する

キャンバスを作成できたので、新しいセッションを開始して使用します。

  1. Copilot app で tailspin-toys の横にある New session を選択し、新しいセッションを開始します。
  2. 次のプロンプトを使い、トリアージ用キャンバスを開くよう Copilot に依頼します。
Issue の優先順位を整理する canvas を開いてください。
  1. 作成したキャンバスが新しいセッションで開いたことを確認します。
  2. 最も関心のある Issue の1つで Add to current session を選択します。表示名は生成したキャンバスの定義によります。実走のボタン名はこの表記でした。
  3. Issue の内容が現在のセッションに届くことを確認します。実走では計画用コンテキストへ追加して確認応答を返すところまでとし、Issue の実装は開始しませんでした。実装を進める場合は、対象と範囲を確認してから依頼します。

反復送信への対処： 初版では、通知の「Issue を追加する」という命令を受けてエージェントが追加アクションを再び呼び、通知が反復しました。Stop で処理を停止し、通知を「追加済み」の事実通知へ修正。同じ Issue の送信中・送信済みを追跡し、再入時に元の送信を待たず返す処理と回帰テストを加えました。修正後は1回のクリックで1通知・1応答となり、Refresh 後の再クリックでも通知が増えないことを確認しました。表示と保存だけでなく、この操作結果まで確認してください。

これで、作成したキャンバスを使って開発プロセスを効率化できました。

講師向け： 緊急の作業保全が必要な場合だけ 対応手順 を参照してください。CLI の実装成功は、この章の App 操作の完了には数えません。

まとめと次のステップ

ユーザーとエージェントが共同作業できる共有領域を作成しました。具体的には、次の作業を行いました。

  • キャンバスの概要と使用する場面を学習した。
  • エージェントと共有の Kanban トリアージボードのキャンバスを作成した。
  • Agent Merge を使ってキャンバスをリポジトリに保存し、マージした。
  • 新しいセッションでキャンバスを開き、そこから作業を開始した。
