開発環境のセットアップを行うと同時に、コードベースの基本構造や規約を Copilot へ的確に伝達します。あらかじめプロジェクトのコンテキストを設計しておくことで、以降の各演習においてエージェントのコード生成精度を最大限に引き出すことができます。

セクション1：初期セットアップ

手順1：個人用リポジトリを作成する

  1. ブラウザーで mona-mayhem リポジトリ（github.com/copilot-dev-days/mona-mayhem） を開きます。
  2. 画面右上の Use this template → Create a new repository を選択（またはフォーク）し、自身のアカウント配下に新しいリポジトリを作成します。
  3. テンプレートから作成する場合は、リポジトリ名を my-mona-mayhem とし、公開設定（Visibility）を Public に指定してください。

VS Code トラック：手順2 — 開発環境の選択と起動

以下のいずれか都合の良い環境を選択してください。

選択肢A：ローカル端末の VS Code を使用する場合

  1. VS Code を開き、コマンドパレット（F1 または Ctrl/Cmd+Shift+P）から Git: Clone を実行して作成したリポジトリをクローンします。
  2. クローンしたワークスペースを開き、画面右下に表示される推奨拡張機能のインストール通知に従って必要な拡張機能を導入します。

選択肢B：GitHub Codespaces を使用する場合

  1. GitHub 上で自身のリポジトリページを開きます。
  2. 緑色の Code ボタンをクリックし、Codespaces タブから Create codespace on main を選択します。
  3. コンテナ環境の構築と依存関係の初期化が完了するまで待機します。

VS Code トラック：手順3 — 依存関係のインストールと起動確認

VS Code 内で統合ターミナルを開き、以下のコマンドを順に実行します。

npm install
npm run dev

ターミナルに出力されたローカル URL（通常は http://localhost:4321）をブラウザーで開き、初期画面が正常に表示されることを確認します。

CLI トラック：手順2 — GitHub Copilot CLI のインストール

利用環境に合わせて以下のいずれかのパッケージマネージャーを使用します。

npm を使用する場合（全プラットフォーム共通／Node.js 22 以上必須）

npm install -g @github/copilot

Homebrew を使用する場合（macOS / Linux）

brew install --cask copilot-cli

補足 Homebrew の導入コマンドは、公式インストール手順 に準拠して --cask オプションを付与しています。

WinGet を使用する場合（Windows）

winget install GitHub.Copilot

CLI トラック：手順3 — アプリの起動と CLI 認証

  1. 演習用リポジトリをローカルにクローンし、リポジトリルートでターミナルを開きます。
  2. 依存パッケージをインストールし、開発サーバーを起動します。
npm install
npm run dev
  1. 同じリポジトリルートで2つ目のターミナルタブを新設し、Copilot CLI を起動します。
copilot
  1. 対話プロンプトで /login を入力して認証を開始します。
  2. ターミナルに表示されるデバイスコード認証の案内に従ってブラウザーで承認を行い、対象リポジトリが自身の演習用リポジトリであることを確認します。

これで、一方のターミナルで Web アプリのプレビューサーバーが稼働し、もう一方のターミナルで Copilot CLI の対話セッションが待機している状態が整いました。

セクション2：コンテキストの設計

コンテキストの設計とは、AI エージェントがコードベースの全体像、設計思想、コーディング規約を正確に理解できるよう、前提情報をあらかじめ構造化して提供する工程です。コンテキストが明確であるほど、生成されるコードのブレや手戻りを最小限に抑えられます。

共通タスク1：/init による指示ファイルの自動生成

  1. Copilot Chat（VS Code）または Copilot CLI のプロンプトに以下の指示を入力して送信します。
/init プロジェクトの概要、ビルド・開発用コマンド、Astro のベストプラクティスを含む簡潔な指示を作成してください。ワークショップ教材は対象から除外してください。
  1. 自動生成された .github/copilot-instructions.md の内容を精査します。
  2. 提示された内容に問題がなければ採用し、指示ファイルを Git にコミットします。

以降のリクエストやセッションにおいて、エージェントはこのリポジトリ固有の指示を前提として自律動作するようになります。

VS Code トラック：タスク2 — バックグラウンドエージェントの活用

ローカルのバックグラウンドエージェント

  1. Chat パネル上部の +（New Chat）をクリックして新しいチャットを開始します。
  2. チャット入力欄下部の実行環境ドロップダウン（初期値: Local）を Copilot CLI に変更します。
  3. 次の指示を入力して送信します。
未使用変数に対する lint ルールを追加してコードスタイルを改善し、エラーを修正してください。
  1. エージェントの作業完了後、Review and Apply をクリックして生成された変更差分をレビューし、問題がなければ適用します（必要に応じて完了したセッションをアーカイブします）。

クラウドエージェント

  1. + をクリックして新しいチャットを開き、実行環境を Cloud に切り替えます。
  2. 次のプロンプトを送信します。
README を、プロジェクトの魅力が伝わるランディングページとして改善してください。

GUI エディターを離れることなく、コード品質の向上やドキュメントの改善タスクをバックグラウンドで並行処理させることができます。

VS Code トラック：タスク3 — プロジェクト構造の対話探索

Copilot Chat の Ask モード（または通常のチャット）で、コードベースに関する質問を投げかけてみます。

  • このプロジェクトのアーキテクチャを説明してください
  • src ディレクトリにはどのようなファイルがあり、それぞれ何をしますか？
  • Battle ボタンを動かすには、何を実装する必要がありますか？

ヒント プロンプトに @workspace を付与することで、ワークスペース全体を検索対象コンテキストとしてエージェントに走査させることができます。

CLI トラック：タスク2 — CLI 動作環境の確認と権限調整

  1. /help を入力し、利用可能なスラッシュコマンドの一覧を確認します。
  2. /model を入力し、現在選択されている LLM モデルを確認します。
  3. 試行錯誤の過程でツールの自動実行権限を記憶させすぎた場合は、以下のコマンドで安全にリセットできます。
/reset-allowed-tools
  1. プロジェクト外の親ディレクトリや特定パスを参照させる必要がある場合は、/add-dir PATH を使用してアクセス許可パスを追加します（PATH には実際の対象ディレクトリを指定してください）。

CLI トラック：タスク3 — ターミナルからのコードベース探索

プロンプトに @ 記法を用いて特定のファイルパスを明示し、ピンポイントで調査を依頼します。

このプロジェクトの概要を説明してください。
@src/pages/api/contributions/[username].ts このファイルの役割と、ここに実装すべき内容を説明してください。
@src/pages/index.astro すでにある内容と、対戦ページを作るために追加すべき内容を説明してください。

対話セッションを起動せず、シェルのワンライナーとして単発で質問することも可能です。

copilot -p "このリポジトリのアーキテクチャを5項目で要約してください"
