開発環境を準備すると同時に、コードベースについて Copilot に伝えます。これにより、以降のプロンプトで必要なコンテキストを利用できます。

セクション1：初期設定

手順1：自分のリポジトリを作る

  1. mona-mayhem リポジトリを開きます。
  2. Use this template → Create a new repository を選ぶか、fork して自分のリポジトリを作ります。
  3. テンプレートから作る場合は、名前を my-mona-mayhem、公開範囲を Public にします。

VS Code：手順2 — 開発環境を選ぶ

選択肢A：ローカルの VS Code

  1. VS Code で Git: Clone → Clone from GitHub を実行します。
  2. 自分の my-mona-mayhem を選択します。
  3. 案内されたら、推奨拡張機能をインストールします。

選択肢B：GitHub Codespaces

  1. GitHub で自分のリポジトリを開きます。
  2. Code → Codespaces → Create codespace on main を選択します。
  3. 環境の起動と依存関係の導入が終わるまで待ちます。

VS Code：手順3 — 依存関係を導入して起動する

リポジトリ内で統合ターミナルを開き、順に実行します。

npm install
npm run dev

起動ログに表示された URL をブラウザーで開き、アプリが表示されることを確認します。

CLI：手順2 — GitHub Copilot CLI を導入する

自分の環境に合う方法を一つ選びます。

npm（全プラットフォーム、Node.js 22以上が必要）

npm install -g @github/copilot

Homebrew（macOS / Linux）

brew install --cask copilot-cli

日本語版の補足： Homebrew のコマンドは、原文の brew install copilot-cli から公式の導入手順に合わせています。

WinGet（Windows）

winget install GitHub.Copilot

CLI：手順3 — アプリを起動し、CLI を認証する

  1. 自分のリポジトリをローカルに clone し、プロジェクトのルートでターミナルを開きます。

  2. 依存関係を導入してアプリを起動します。

    npm install
npm run dev

  3. 同じリポジトリで2つ目のターミナルを開きます。

    copilot

  4. 対話セッションで /login を入力します。

  5. デバイス認証の案内に従い、許可を求められたら対象が自分の演習リポジトリであることを確認します。

これで、一方のターミナルではアプリのプレビュー、もう一方では Copilot CLI が動いています。

セクション2：コンテキストを設計する

コンテキストの設計とは、AI にコードベースを理解してもらうための情報を整えることです。情報が適切であるほど、その後の回答も目的に合いやすくなります。

共通：タスク1 — /init で指示を作る

  1. Copilot Chat または CLI に入力します。

    /init プロジェクトの概要、ビルド・開発用コマンド、Astro のベストプラクティスを含む簡潔な指示を作成してください。ワークショップ教材は対象から除外してください。

  2. 生成された .github/copilot-instructions.md を確認します。

  3. 内容を確認して採用し、指示ファイルを commit します。

以降のリクエストや CLI セッションで、リポジトリ固有の指示を利用できます。

VS Code：タスク2 — バックグラウンドエージェント

ローカルのバックグラウンドエージェント

  1. Chat パネルの + で新しいチャットを開始します。
  2. 下部の Local を Copilot CLI に変更します。

  3. 次のように依頼します。

    未使用変数に対する lint ルールを追加してコードスタイルを改善し、エラーを修正してください。

  4. 完了したら Review and Apply で変更を確認して適用します。必要ならセッションをアーカイブします。

クラウドエージェント

  1. + で新しいチャットを作成し、下部の Local を Cloud に変更します。

  2. 次のように依頼します。

    README を、プロジェクトの魅力が伝わるランディングページとして改善してください。

エディターを離れずに、lint ルール、エラー修正、README の改善を進められます。

VS Code：タスク3 — プロジェクトを調べる

Copilot Chat の Ask モードで試します。

  • 「このプロジェクトのアーキテクチャを説明してください」
  • 「src ディレクトリにはどのようなファイルがあり、それぞれ何をしますか？」
  • 「Battle ボタンを動かすには、何を実装する必要がありますか？」

@workspace を使うと、プロジェクト全体をコンテキストとして指定できます。

CLI：タスク2 — CLI の環境を調整する

  1. /help で使えるスラッシュコマンドを確認します。
  2. /model で利用できるモデルを確認します。

  3. 試行中に許可を記憶させすぎた場合は、次でリセットできます。

    /reset-allowed-tools

  4. 親ディレクトリなどを参照する必要がある場合は、/add-dir PATH で必要な範囲を追加します。PATH を実際に許可するディレクトリへ置き換えてください。

簡潔なカスタム指示と、明示的なツール権限で作業範囲を整えます。

CLI：タスク3 — ターミナルからプロジェクトを調べる

次のプロンプトを一つずつ試します。

このプロジェクトの概要を説明してください。
@src/pages/api/contributions/[username].ts このファイルの役割と、ここに実装すべき内容を説明してください。
@src/pages/index.astro すでにある内容と、対戦ページを作るために追加すべき内容を説明してください。

対話セッションの外から、一度だけ質問することもできます。

copilot -p "このリポジトリのアーキテクチャを5項目で要約してください"

✅ 第1章の完了

  • リポジトリと開発環境を準備した。
  • /init でプロジェクトとデザイン方針の指示を作った。
  • 生成された変更を採用前に確認した。
  • ファイルやプロジェクトの情報を指定してコードを調べた。
