第4章：デザインからテーマを作る

計画（Plan）と実装（Agent）の反復サイクルを活用して、Web ページ全体のデザインテーマを一新します。あらかじめ目指すべき視覚的コンセプトを整理し、ブラウザー上の描画結果を確認しながら微調整を重ねることで、複雑な CSS 実装を Copilot に効率よく任せられます。

タスク1：レトロなテーマを計画する

  1. 計画モードへ切り替えます。 - VS Code： Copilot Chat パネルのモード選択で Plan を指定します。 - CLI： コマンド /plan を実行するか、Shift+Tab を押して計画モードに切り替えます。

  2. 次のプロンプトを入力して送信します。

    このページを本格的なレトロアーケード風に変更したいです。次を含む見た目の全面改修を計画してください。
背景の CRT 走査線、ネオンサインのように明滅するタイトル、グラデーションが変化する VS バッジ、
ユーザー結果カードの光沢オーバーレイ、入力欄が浮かび上がるアニメーション、
緑と紫に変化する読み込み中の文字、グラフの四角形をホバーしたときの発光を含めてください。
暗い背景 #0a0a1a と、緑 #5fed83・紫 #8a2be2 のアクセントを維持してください。
Google Fonts の Press Start 2P を使うダークテーマにしてください。

  3. 提案された計画をそのまま盲目的に採用せず、意図した演出が含まれているかを精査します。 - アニメーション時間の調整： 「ネオンの明滅を約 3 秒のゆっくりした周期にしてください」のようにテンポを指定します。 - 詳細仕様の確認： 「カードの光沢オーバーレイはどう動きますか？」と具体的な実装アプローチを質問します。 - 演出の変更： 違和感がある部分や過剰な効果があれば、代替手段を提示してもらいます。

タスク2：テーマを実装する

  1. 提示された計画に納得できたら、実装を指示します。

    今確認したレトロアーケードのテーマ計画を実装してください。

  2. スタイルシートに対して、次のような CSS 構造が追加・変更されることを確認します。 - 走査線、ネオンの明滅、光沢、浮き上がり演出を定義する @keyframes - 装飾オーバーレイを描画するための疑似要素（::before / ::after） - テーマカラーを一括管理する CSS カスタムプロパティ（CSS 変数） - 各操作要素のトランジション（transition）およびホバー状態（:hover）のスタイル

  3. CLI を使用している場合は、/diff コマンドでスタイルの変更差分をレビューしたうえで採用を確定します。

タスク3：見た目を微調整する

ヒント 画面の表示が更新されない場合： 開発サーバーを実行中のターミナルで Ctrl+C を押して停止し、npm run dev で再起動したうえで、ブラウザーで Ctrl+Shift+R（強力な再読み込み）を実行してください。

ブラウザーのプレビュー画面を開いた状態で、細部のニュアンスを整える追加指示を試します。

  • 「走査線の効果が強すぎるので、不透明度を 0.03 に落としてください」
  • 「メインタイトルに、蛍光灯の電気がかすかにちらつくような控えめなアニメーションを追加してください」
  • 「VS バッジのパルス発光をもっと強調して目立たせてください」

実際の画面描画を確かめながら、レトロアーケード筐体の世界観に合致するまでプロンプトで微調整を繰り返します。

タスク4：指示ファイルを更新する

確定した重要なデザイン方針をリポジトリの指示ファイルへ明文化し、今後追加される別の機能や UI でも一貫したデザイン言語が維持されるようにします。

  • VS Code の場合のプロンプト：

    copilot-instructions.md にデザインガイドの節を追加し、レトロアーケードの配色、フォント、アニメーションの方針を記載してください。

  • CLI の場合のプロンプト：

    リポジトリの指示に、レトロアーケードの短いデザインガイドを追加してください。
配色、フォント、アニメーションの方針と、新しい UI でもネオンの見た目を維持するルールを含めてください。

ブラウザーでの最終表示を確認できたら、指示ファイルとデザイン関連の変更内容を git commit します。

✅ 第4章の完了チェック

  • コード実装を始める前に、目指すデザイン方針と演出要件を Copilot と綿密に計画した。
  • 短く焦点を絞ったプロンプトを反復し、ブラウザープレビューを見ながら見た目を微調整した。
  • 確定したデザインルールを指示ファイルへ記録し、将来の実装でもトーン＆マナーが一貫する土台を整えた。
