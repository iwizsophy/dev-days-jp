コードを書く前に、Copilot の計画機能でアーキテクチャを検討します。計画を先に立てることで、システムの構造を考え、コード生成に必要な情報を渡せます。

タスク1：API の構造を計画する

  1. VS Code： Chat パネル下部のモード選択で Plan に切り替えます。CLI： Shift+Tab で計画モードへ移るか、/plan を使います。

  2. 次のプロンプトを入力します。

    任意のユーザー名について GitHub のコントリビューションデータを取得する、サーバー側の API プロキシを作りたいです。
エンドポイントは https://github.com/{username}.contribs で、JSON を返します。
ブラウザーから直接取得した際の CORS 制約を避けるため、サーバー側で取得します。
ルートの構造、エラー処理、キャッシュ戦略を含めて実装を計画してください。

  3. 計画をレビューします。不明点を質問し、違和感があれば変更を提案して、納得できるまで調整します。

  4. VS Code： Agent モードに切り替えて実装を依頼します。CLI： 確認済みの計画の実装を依頼し、/diff で編集結果を確認します。

  5. 次の API ルートが作成されていることを確認します。

    src/pages/api/contributions/[username].ts

日本語版の補足： .contribs の応答形式は原文の前提です。実際の HTTP ステータスと Content-Type、レスポンスを確認し、一致しなければ講師と取得方法を確認してください。認証情報をクライアント側に埋め込んで解決しないでください。

タスク2：API をテストする

変更が反映されない場合： 開発サーバーを Ctrl+C で停止し、npm run dev で再起動します。

  1. 開発サーバーが動いていることを確認し、別のターミナルから実行します。

    curl http://localhost:4321/api/contributions/octocat

  2. コントリビューションデータを含む JSON が返ることを確認します。

  3. 無効なユーザー名でも試し、適切なエラーレスポンスを返すことを確認します。

タスク3：対戦ページを計画する

  1. Plan モードへ戻ります。CLI では /plan も使えます。

  2. 次を入力します。

    次にメインページが必要です。「Mona Mayhem - GitHub Contribution Battle Arena」の対戦ページを計画してください。
Player 1 と Player 2 のユーザー名入力欄、対戦ボタン、結果表示領域を用意します。
この段階ではレイアウトや装飾を作り込みすぎず、シンプルな UI にしてください。
HTML の構造、基本的なスタイル、対戦操作の流れを計画してください。

  3. 計画を読み、質問や変更提案を通じて改善します。

  4. VS Code： Agent モードで実装します。CLI： 計画の実装を依頼し、/diff で HTML と CSS のひな形を確認します。

タスク4：ひな形を確認する

  1. ブラウザーで http://localhost:4321 を開きます。
  2. ゲームのタイトル、2つのユーザー名入力欄、対戦ボタンがあることを確認します。
  3. ボタンがまだ動かなくても正常です。 操作とデータをつなぐ処理は次章で実装します。

表示が更新されない場合は、開発サーバーを再起動してブラウザーを更新します。

✅ 第2章の完了

  • 実装前に計画を立てた。
  • アーキテクチャに納得できるまで計画を調整した。
  • 計画から実装へ進み、API とページのひな形を確認した。
