この章では、Copilot に計画だけでなく実装を担当してもらいます。一行ずつコードを書く代わりに、実現したいことを説明し、必要なファイルを変更してもらいます。

タスク1：対戦処理をつなぐ

  1. VS Code： Copilot Chat を Agent モードにします。CLI： 通常のコーディングの流れへ戻ります。自律的に継続させたい場合は Autopilot を利用する選択肢もあります。
  2. CLI では必要に応じて @src/pages/index.astro を指定し、ページをコンテキストに追加します。

  3. 次のプロンプトを入力します。

    対戦ページに、次を行うクライアント側 JavaScript を追加してください。
1. Battle ボタンが押されたら、両方の入力欄からユーザー名を取得する。
2. 両方が入力されているか確認し、空ならエラーを表示する。
3. 自分たちの API から、2人のコントリビューションデータを並列で取得する。
4. GitHub の配色を使い、1日を1つの色付き四角形としたグリッドでグラフを描画する。
5. 2人の間に VS バッジを表示する。
6. それぞれのユーザー名、コントリビューション合計、対象期間を表示する。
7. 読み込み中とエラーの状態に対応する。
8. 入力欄で Enter キーを押したときにも対戦を開始する。
9. 今は作成済みのシンプルな UI を使う。
コントリビューションデータの構造には TypeScript の interface を使ってください。

  4. src/pages/index.astro などに対する実装が進むのを確認します。

  5. VS Code の差分表示、または CLI の /diff で変更内容を確認して採用します。

タスク2：対戦をテストする

変更が見えない場合は、開発サーバーを Ctrl+C で停止し、npm run dev で再起動してブラウザーを更新します。

  1. ユーザー名に octocat と torvalds を入力し、Battle を押します。
  2. 色付きのグリッドで2人のグラフが横に並ぶことを確認します。
  3. 片方または両方を空にして、入力エラーが表示されることを確認します。
  4. 無効なユーザー名で、API のエラーが表示されることを確認します。
  5. どちらの入力欄でも Enter キーで対戦を開始できることを確認します。

タスク3：フィードバックで改善する

期待と違う場合は、具体的に追加指示を出します。

  • 「グラフの四角形が大きすぎるので、12×12px にしてください」
  • 「ホバー時に日付とコントリビューション数を表示するツールチップを追加してください」
  • 「読み込み中の表示にパルスアニメーションを追加してください」

VS Code の Agent モードでは、複数ファイルの変更や反復を同じ会話で続けられます。CLI でもセッションの履歴を踏まえて追加指示を出せます。引き継いでいる情報は /session や /context、大きな変更後の追加レビューは /review で確認できます。

この章のヒント

  • 求める動作を具体的に伝える。
  • 意図から外れたら、大きな課題を小さなプロンプトに分ける。
  • 採用前に変更をレビューする。
  • 実装のたびにすぐ動作を確認し、問題の場所を絞る。

✅ 第3章の完了

  • Copilot に複数ファイルの実装を依頼した。
  • 焦点を絞った追加指示で結果を改善した。
  • 実装、レビュー、テスト、調整という機能開発の一連の流れを体験した。
