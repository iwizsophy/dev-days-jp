GitHub 上のコントリビューション（活動量）を比較して遊ぶレトロアーケード風 Web アプリ Mona Mayhem の開発を通じて、GitHub Copilot を活用した実践的なエージェント開発ワークフローを学びます。本ワークショップは、VS Code トラック と GitHub Copilot CLI トラック の2つの学習コースから選択して進められます。

🎯 トラックの選択

  • VS Code トラック： GUI エディター内で、Chat、Plan Mode、Agent Mode、バックグラウンドエージェント、および組み込みの差分レビュー機能を活用して開発を進めます。
  • CLI トラック： ターミナル環境で copilot コマンドを起点とし、@file によるコンテキスト指定、/plan、自律コード生成、/fleet、/delegate、/review などのコマンドを駆使して開発を進めます。

ご自身の開発スタイルや好みのツール環境に合わせて選択してください。本日本語版教材では各章に両トラックの手順を併記しています。ご自身が選択したトラックの手順に沿って作業を進め、共通の解説や検証ステップへ合流してください。

📋 事前チェック項目

作業を開始する前に、以下の動作環境が整っていることを確認してください。

  • GitHub アカウントで GitHub Copilot の利用権限が有効化されている
  • 端末に Node.js がインストールされている
  • Git がインストールされ、初期設定が完了している
  • 動作確認用の Web ブラウザーおよびターミナル環境が利用可能である

VS Code トラックを選択する場合

  • VS Code v1.107 以上 がインストールされており、適用待ちの更新がない
  • GitHub Copilot 拡張機能がインストールされ、自身のアカウントでサインイン済みである
  • Copilot Chat パネルを開き、エージェント機能（Agent Mode 等）が呼び出せる

CLI トラックを選択する場合

  • GitHub Copilot CLI がインストールされており、ターミナルで copilot コマンドが実行できる
  • /login（または初回起動時の認証フロー）により GitHub アカウントで認証済みである
  • /help、/plan、/review などのスラッシュコマンドが正常に認識される

ヒント VS Code 環境を手早く整えたい場合は、リポジトリに同梱されている設定済みの DevContainer を利用することで、依存ツール一式が自動構成された環境で即座に開始できます。

🧠 本ワークショップで習得するスキル

番号 スキル領域 学習内容
1 コンテキストの設計 明確な指示、参照ファイル、および設計上の制約条件を通じて、コードベースの前提を Copilot へ的確に伝達する
2 計画主導の開発 いきなりコードを書かせるのではなく、事前のアーキテクチャ検討と実装計画（Plan）の策定から着手する
3 自律エージェントによる実装 人間が適切な監督とレビューを行いつつ、複数ファイルにまたがるコード生成・編集作業をエージェントへ委任する
4 反復的なデザイン調整 プロンプトを通じて Web サイトの外観テーマを改修し、操作性やアクセシビリティの細部を反復的に調整する
5 タスクの並列処理 複数のエージェント、セッション、および非同期クラウド委任を活用し、時間のかかるタスクを並行処理する

VS Code トラックで重点的に活用する機能

  • Chat と Ask モード： コードベースの探索と仕様の確認
  • Plan Mode： アーキテクチャの検討と段階的な実装計画の策定
  • Agent Mode： 複数ファイルにまたがる自律的なコード実装
  • バックグラウンド／クラウドエージェント： 時間のかかるリファクタリングや品質向上の非同期並列実行

CLI トラックで重点的に活用する機能

  • copilot コマンドによる対話型エージェントセッション
  • /plan コマンドおよび Shift+Tab による実装計画の策定
  • 実行権限の承認と /diff コマンドによる自律編集と差分レビュー
  • /fleet、/delegate、/review コマンドによるタスク並列処理とコード品質検証

💡 スムーズに進めるためのヒント

  1. 開発用ブラウザーを常に開いておく： コードの変更が画面にどう反映されたかを即座に目視確認します。
  2. こまめにコミットを作成する： 正常に動作しているチェックポイントをこまめに保存し、いつでも安全に巻き戻せる状態を維持します。
  3. 実装前に計画（Plan）を徹底的に練る： 計画段階で要件や設計を具体化しておくほど、生成されたコードの妥当性を迅速に判断できます。
  4. 差分（diff）を必ず人間がレビューする： エディターの差分ビューや CLI の /diff を活用し、変更内容を精査したうえで適用します。
  5. 手戻りへの対処： 生成結果が意図と乖離した場合は、VS Code では Chat のチェックポイントや Undo 機能を活用し、CLI では /session、/context、/share file を用いて作業履歴を適切に管理・保存してください。
