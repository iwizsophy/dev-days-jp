アプリが動き、見た目が整ったら、細部を仕上げます。作業を分割して、レスポンシブ対応、エラー処理、品質の改善を進めます。

VS Code：タスク1 — レスポンシブ対応をバックグラウンドで進める

  1. Chat パネルの + で新しいチャットを開始します。
  2. 下部の Local を Copilot CLI に変更します。

  3. 次のプロンプトを入力します。

    レスポンシブな CSS メディアクエリを追加してください。
1024px で比較表示を1列にし、768px で文字を小さくして入力欄を縦に並べ、モバイル向けにしてください。
キーボード操作も改善し、Tab の移動順、Enter による対戦開始、見えるフォーカス表示を確認してください。

  4. 独立して実行させます。常に画面を見ている必要はありません。

  5. 完了したら Review で確認し、Apply で適用します。

VS Code：タスク2 — エラー時の UX を改善する

  1. 別のバックグラウンドエージェントを開始します。

  2. 次を入力します。

    エラー時の体験を改善してください。揺れるアニメーション、アーケードテーマに合う赤 #ff3366 のネオン発光を使ったエラーメッセージ、より分かりやすい入力チェックのフィードバックを追加してください。
ユーザー名が空または無効な場合に、明確なエラーメッセージを表示してください。

  3. 完了したら変更を確認し、Apply を選びます。

VS Code：タスク3 — クラウドで別テーマを作る（任意）

  1. + で新しいチャットを作り、下部の Local を Cloud に変更します。

  2. 次を入力します。

    対戦ページの別配色を作ってください。レトロアーケードの雰囲気を保ち、緑と紫の代わりに青 #00f5ff とオレンジ #ff6b35 を使ってください。
切り替え可能な CSS カスタムプロパティのテーマにしてください。

  3. agent sessions で進行状況を確認します。

  4. クラウドエージェントが作った PR で別テーマをレビューします。

CLI：タスク1 — /fleet で作業を分割する

並列のサブエージェントに分け、最後に統合された変更を確認します。

/fleet 次の改善を並列で進めてください。
1. 1024px で比較表示が1列になり、小さい画面では入力欄が縦に並ぶ CSS メディアクエリを追加する。
2. キーボード操作とフォーカスの視認性を改善する。
3. 入力チェックのフィードバックと、アーケード風のネオンを使ったエラー表示を改善する。

作業が終わったら、/diff で統合された結果を確認して採用します。

CLI：タスク2 — 別テーマを委任する（任意）

非同期のクラウド作業を試す場合は、次を入力します。

/delegate 対戦ページの別テーマを作成してください。レトロアーケードの雰囲気を維持し、青 #00f5ff とオレンジ #ff6b35 に変更してください。簡単に切り替えられるようにしてください。

委任したタスクが作る PR は、ローカル作業を続けながら別途レビューできます。

CLI：タスク3 — レビューを依頼する

/review 現在のブランチにあるバグの可能性、アクセシビリティの問題、UX の退行を重点的に確認してください。

指摘を確認し、妥当なものを修正します。その後 /diff で変更を把握します。

日本語版の補足： /fleet やクラウドへの委任が利用できない場合は、一つずつ通常の対話で依頼して進められます。並列・委任の体験は未実施として記録してください。

共通：タスク4 — 全体を検証する

反映されない場合は開発サーバーを停止・再起動し、ブラウザーを Ctrl+Shift+R で更新します。

テスト 期待する結果
空の入力欄で Battle 揺れるアニメーション付きのエラー表示
有効なユーザー名 コントリビューショングラフを表示
無効なユーザー名 テーマに合う表示で API エラーを案内
入力欄で Enter 対戦が始まる
モバイル幅 1列のレスポンシブ表示
グラフの四角形をホバー 日付と件数のツールチップ

本番向けビルドを実行し、成功したらプレビューします。

npm run build
npm run preview

日本語版の補足： 原文の npm run build && npm run preview を、シェル差を避けるため分けています。ビルドが失敗したら修正してから preview を実行してください。

確認が終わったら、動作するコードを commit します。

✅ 第5章の完了

  • 仕上げの作業を小さな並列タスクに分けた。
  • main ブランチへ統合する前に生成された変更をレビューした。
  • 実装だけでなく、品質確認や任意の実験にも Copilot を使った。
