アプリケーションの基本機能が動作し、デザインの方向性が定まったら、プロダクション品質を目指して細部を磨き上げます。タスクを適切に分割し、バックグラウンド実行や並列エージェントを活用することで、レスポンシブ対応、エラーハンドリング、コード品質の向上を効率的に進めます。

VS Code トラック

タスク1：レスポンシブ対応をバックグラウンドで進める

  1. Chat パネル上部の + アイコンをクリックして、新しいチャットセッションを開始します。
  2. 入力欄下部にある実行環境の選択肢を Local から Copilot CLI に変更します。

  3. 次のプロンプトを入力して送信します。

    レスポンシブな CSS メディアクエリを追加してください。
1024px で比較表示を1列にし、768px で文字を小さくして入力欄を縦に並べ、モバイル向けにしてください。
キーボード操作も改善し、Tab の移動順、Enter による対戦開始、見えるフォーカス表示を確認してください。

  4. エージェントが独立してバックグラウンドで処理を進めます。作業の完了を画面の前で待ち続ける必要はありません。

  5. タスクが完了したら、Review をクリックして生成された差分を確認し、問題がなければ Apply を選択して適用します。

タスク2：エラー時の UX を改善する

  1. 再度 + をクリックし、別のバックグラウンドエージェントを立ち上げます。

  2. 次のプロンプトを入力して送信します。

    エラー時の体験を改善してください。揺れるアニメーション、アーケードテーマに合う赤 #ff3366 のネオン発光を使ったエラーメッセージ、より分かりやすい入力チェックのフィードバックを追加してください。
ユーザー名が空または無効な場合に、明確なエラーメッセージを表示してください。

  3. 処理が完了したら変更内容をレビューし、Apply をクリックして取り込みます。

タスク3：クラウドエージェントで別テーマを作成する（任意）

  1. + をクリックして新規チャットを作成し、下部の実行環境を Local から Cloud に変更します。

  2. 次のプロンプトを入力して送信します。

    対戦ページの別配色を作ってください。レトロアーケードの雰囲気を保ち、緑と紫の代わりに青 #00f5ff とオレンジ #ff6b35 を使ってください。
切り替え可能な CSS カスタムプロパティのテーマにしてください。

  3. agent sessions 一覧から、クラウド上でのタスク進行状況を確認します。

  4. クラウドエージェントによって作成されたプルリクエスト（PR）上で、別テーマの実装内容をレビューします。

CLI トラック

タスク1：/fleet で作業を分割・並列実行する

複数のサブエージェントへタスクを並列に分散させ、最終的に統合された変更内容を一括で確認します。

/fleet 次の改善を並列で進めてください。
1. 1024px で比較表示が1列になり、小さい画面では入力欄が縦に並ぶ CSS メディアクエリを追加する。
2. キーボード操作とフォーカスの視認性を改善する。
3. 入力チェックのフィードバックと、アーケード風のネオンを使ったエラー表示を改善する。

サブエージェント群による作業が完了したら、/diff コマンドで統合された修正結果を確認し、採用を確定します。

タスク2：別テーマの作成をクラウドへ委任する（任意）

非同期のクラウド実行を体験する場合は、次のコマンドを入力します。

/delegate 対戦ページの別テーマを作成してください。レトロアーケードの雰囲気を維持し、青 #00f5ff とオレンジ #ff6b35 に変更してください。簡単に切り替えられるようにしてください。

クラウドへ委任されたタスクは自動的にプルリクエスト（PR）を作成するため、ローカル環境での作業を中断することなく、あとから GitHub 上で別途レビューできます。

タスク3：コード全体のレビューを依頼する

/review 現在のブランチにあるバグの可能性、アクセシビリティの問題、UX の退行を重点的に確認してください。

Copilot から提示された指摘事項を確認し、妥当と判断した箇所を修正します。修正後は /diff で変更の全容を把握してください。

補足 日本語版の補足： ご利用の環境や権限によって /fleet やクラウドへの委任（/delegate）が利用できない場合は、通常の対話形式で 1 つずつプロンプトを送信して進めれば問題ありません。その際は、並列実行・クラウド委任の項目を未実施として記録してください。

共通：タスク4 — アプリケーション全体を検証する

ヒント 変更が反映されない場合： 開発サーバーを Ctrl+C で停止して再起動し、ブラウザーで Ctrl+Shift+R を押してキャッシュを破棄した再読み込みを行ってください。

次のテスト項目を実施し、すべての機能と演出が正しく動作することを確認します。

テスト項目 期待される動作・結果
入力欄を空にして Battle を実行 画面が揺れるアニメーションとともにエラーメッセージが表示される
有効な GitHub ユーザー名を入力 2 人分のコントリビューショングラフが正常に描画される
存在しない無効なユーザー名を入力 アーケードテーマに馴染むデザインで API エラーが案内される
入力欄にフォーカスして Enter キー押下 ボタンクリック時と同様に対戦が開始される
ウィンドウ幅をモバイル幅まで縮小 1 列表示のレスポンシブレイアウトへ切り替わる
グラフの各四角形にマウスホバー 日付とコントリビューション件数を示すツールチップが表示される

本番向けビルドとプレビューの実行

本番用ビルドを実行し、エラーなく完了することを確認したうえでプレビューサーバーを起動します。

npm run build
npm run preview

補足 日本語版の補足： 原文では npm run build && npm run preview と 1 行で記述されていますが、Windows PowerShell などのシェル差異による失敗を避けるため、コマンドを 2 行に分割しています。もし npm run build が失敗した場合は、エラー原因を解消してから npm run preview を実行してください。

プレビューでの最終動作確認が完了したら、正常に動作するコード一式を git commit します。

✅ 第5章の完了チェック

  • 仕上げの作業を複数の小さなタスクに分解し、バックグラウンド実行や並列エージェントを活用して効率化を図った。
  • main ブランチへの統合に先立ち、生成されたコードの差分を綿密にレビューした。
  • 単なるコード生成にとどまらず、品質チェックや別配色の実験といった発展的な作業にも Copilot を活用した。
