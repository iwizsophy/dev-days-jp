事前準備と CLI への切り替え

App シナリオの補助資料です。本編の目次から演習0〜8へ進みます。各章に CLI 代替手順と合流条件があります。講師ガイドと章別の検証状況も参照してください。利用条件の参照確認日は2026年9月8日、教材再構成日は2026年9月10日です。

教材のボタン名や画面構成が現在の UI と異なり、そのまま操作できない場合があります。講師と確認しても約5分で解決しない場合は CLI へ切り替え、同じ課題の計画・実装・検証を続けます。この5分は運営上の目安です。

  • 事前準備
  • プラン・利用枠
  • CLI へ切り替える
  • 演習との対応
  • 検証と復帰
  • 講師の準備

1. 開催前に App と予備の CLI を準備する

ノート PC とネット接続、自分の GitHub アカウントを用意します。演習先は自分のコピーです。この案内サイトのリポジトリで演習コマンドを実行しないでください。

本編の準備と確認
コース準備するもの参加前の到達点
Copilot AppGit、Node.js 22.13以上、App、自分の Tailspin Toys テンプレートコピー。日本語の準備手順App で自分のプロジェクトを開き、ファイルの説明を依頼して応答を確認。CLI でも同じ確認を済ませる。

CLI を予備として準備する

演習に使うターミナルで実行します。Windows のローカル実行には PowerShell 6以上が必要です。Node.js の条件を確認したうえで、npm を使う場合は次の順に実行します。

node --version
npm install -g @github/copilot
copilot --version

すでに講師が確認した CLI バージョンが入っていれば、再インストールは不要です。WinGet / Homebrew などの導入方法は 公式インストール手順を参照してください。

自分の演習リポジトリのディレクトリに移動して copilot を実行します。認証を求められたら画面に表示される URL とコードでログインし、信頼するディレクトリが演習用のコピーであることを確認します。次を入力し、正しいプロジェクトについて回答することを確認してください。

このリポジトリの構成と起動・テスト方法を説明してください。ファイルは変更しないでください。

利用可能なコマンドは CLI 内の /help で確認できます。通常のシェルコマンドは別のターミナルで実行するか、CLI に exit を入力して終了してから実行します。

2. プラン名だけでなく、実際に応答できるか確認する

確認日時点の App の公式情報と CLI の公式情報では、全 Copilot プランが対象です。外部教材には Student・有料プランを必須とする古い記述が残っています。利用可否は最新の公式情報と自分のアカウントで確認してください。

  • Free を含め、利用可能な AI クレジット・利用枠の残量を確認します。全演習を無料枠で完走できる保証はありません。
  • 組織の Copilot を使う場合、App 用と CLI 用のポリシーは別です。予備の CLI も管理者に利用可否を確認します。
  • 認証・利用枠・組織ポリシーによる停止は、UI を CLI に変えるだけでは解決しません。講師へ相談し、ペア作業やデモの観察に切り替えます。

3. UI で止まったら、同じ作業場所から CLI で続ける

  1. 講師に「教材の章・やりたい操作・実際の画面・エラー」を伝えます。ボタンの位置だけの違いなら、そのまま進めます。
  2. App やエディター側の実行中エージェントを停止し、編集ファイルを保存します。同じファイルを両方から同時に変更しないでください。
  3. 現在のセッションが使う作業ディレクトリを確認します。App が worktree を作った場合、元の clone と別のディレクトリに変更が入っています。場所が分からなければ講師と確認し、新しく clone し直す前に変更を保全します。クラウド上のセッションは、リモートへ保存したブランチを取得してから続行する必要があります。
  4. そのディレクトリでターミナルを開き、以下を実行します。リポジトリの場所・ブランチ・変更一覧が App の作業内容と一致していることを確認します。
git rev-parse --show-toplevel
git branch --show-current
git status --short
git diff --stat

既存の演習用ブランチなら、そのまま継続します。まだ作業を始めておらず、既定ブランチ上にいて変更がない場合だけ、未使用の名前で演習用ブランチを作ります。例：

git switch -c feature/workshop-cli

ブランチ名が空、想定外の変更がある、ブランチがすでに存在する、といった場合は講師と確認します。reset や clean で変更を消して進めないでください。Codespaces / dev container を使っている場合は、その環境の同じ作業場所で CLI を起動します。

copilot

4. 元の演習との対応

途中から CLI コース全体をやり直す必要はありません。今の課題を続行するための操作を、次の表から選びます。

本編の章CLI での到達点
0–1 準備・接続同じコピーで起動と応答を確認
2 星評価数値・null を検証し、PR・マージ
3 カスタム指示指示と提示コードを確認し、PR・マージ
4 フィルター計画・実装・quality-checks。同じブランチで5へ
5 MCPMCP ツールで検証。手動確認は別扱い

PR 作成・マージ・次章への合流の共通手順

5. 動作を確認し、元の演習へ戻る

  1. README と package.json に定義された起動・テスト・ビルドのコマンドを確認して実行します。教材のリビジョンで異なるため、存在しないスクリプトを推測して実行しません。
  2. 起動ログの URL をブラウザーで開き、課題の完了条件を手で確認します。例：フィルターなら条件に合う結果、該当なし、条件解除。CLI の「完了」という返答だけで判断しません。
  3. シェルで git status --short と git diff を確認します。新規ファイルは diff に出ないため、status に出たファイルも開いて読みます。
  4. 講師と結果を確認します。PR まで行うコースでは、確認済みのファイルだけを commit・push し、自分のリポジトリに PR を作成します。CI とレビューを確認してから教材の指示に従って merge します。
  5. App に戻る場合は CLI の実行を終了し、同じ作業ディレクトリ・ブランチを App で開きます。別の clone に戻る場合は、変更を commit・push して正しいブランチを取得してから再開します。次の章が前の PR の merge を前提にする場合は、先にその前提を満たします。

UI が引き続き使えなければ CLI のまま次の課題へ進めます。最低到達点は「一つの機能を実装し、動作を検証し、差分を説明できること」。省略したスキル・MCP・App 固有機能は別途記録します。

6. 講師のリハーサルと時間配分

1回につき1コースを選び、日本語の演習本文で要件を確認します。演習時間の目安は App 60～90分、Tailspin Toys CLI 120分、Mona Mayhem CLI 60分。別途、導入・切り替えに15分と、質問・休憩の時間を確保してください。

Tailspin Toys CLI の3時間枠の例：導入・接続確認15分、講義30分、演習120分、振り返り・休憩15分。初心者が多い場合は枠を延ばすか、必須範囲を一機能の実装・検証・レビューまでに絞り、残りを発展課題とします。

  • 開催に使う教材コミット、App・CLI・Node.js のバージョン、OS、使うアカウント条件を記録する。
  • 新しい参加者用コピーで最初から一度実行する。Tailspin Toys は自動作成される Issue が存在することも確認する。
  • App の途中から CLI に切り替え、変更が同じ worktree に残ること、検証できること、App に戻れることを確認する。
